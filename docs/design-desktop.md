# 派活工作台桌面应用 设计说明

**状态**：已定稿（2026-09-29），已实现；具体行为以代码和 [ui-spec.md](ui-spec.md) 为准。
**写于**：2026-09-29。
**起因**：把看进度的网页做成正式的桌面应用。旧网页进度页和 `xagents board` 命令已下线。

---

## 1. 要什么，不要什么

**要：**
- 一个 Mac 上的正式应用“派活工作台”，有自己的图标和窗口，放在程序坞里。点开就是看板，看到的永远是真实数据。
- 盯进度不用开着窗口：菜单栏里常驻一个小图标，显示有几件活在跑。
- 负责人拍板或回复留言时弹系统通知。点通知，直接打开对应的任务或批次。
- 能在窗口里直接做决定：“用这份”“不要了”“重做”“停下”，点一下就行，不用再打字告诉负责人；也能给负责人留言。
- 界面的样子（列、状态色、批次色、居中弹窗、只写人话）以 `ui-spec.md` 为准。

**不要：**
- **不在应用里写题目、派新活。** 写题目和决定派给谁，是负责人（Claude）的工作。应用里点“重做”，只是请负责人重派。
- **不在应用里合并代码，也不在应用里验收、清理。** “用这份”只是记下你的决定，合并由负责人来做，并且照旧先验收。
- **应用不开任何网络端口，不连外网。** 查额度时连的是各家自己的程序，不是应用本身在联网。
- **应用不碰选手的隔离设置，也不读任何密钥。**

## 2. 技术选型

| 部分 | 选什么 | 为什么 |
|---|---|---|
| 应用外壳 | **Electron 44**（2026-09-23 发布，自带 Node 24.21、Chromium 152） | 应用的后台部分能直接调用派活工作台现有的核心代码，命令行和应用共用一套逻辑，不用写两遍。|
| 界面 | **React 19 + TypeScript** | 看板有列、卡片、弹窗、分页，用组件写才好维护、好测试 |
| 构建 | **electron-vite**（5.0）+ **electron-builder**（26） | 构建、打包配置已在用；打包安装的真实环境验收待完成 |
| 测试 | 核心逻辑：`node:test`（沿用）<br>界面组件：`vitest` + Testing Library<br>整个应用：Playwright 直接启动 Electron 做冒烟测试 | 三层都有测试才算正式产品；整个应用的测试会真的把窗口开起来点一遍 |

**没选的方案：**
- **Tauri**：体积小，但它的后台用 Rust 写，派活工作台的核心就得用 Rust 再写一遍，或者另开一个进程互相通信。
- **纯 Swift**：最原生，但同样要把核心逻辑再写一遍，也只能在 Mac 上用。

代价是应用体积大（约 150MB），可以接受。

依赖的确切版本由 `package.json` 和 `pnpm-lock.yaml` 固定。

## 3. 结构

```
src/core/        核心：登记处、锁、任务、选手、隔离、额度、自检、验收、统计
src/cli/         命令行：参数解析和输出，只调用 core
app/main/        应用后台：窗口、菜单栏、通知、监视登记处、处理窗口发来的操作
app/preload/     窗口和后台之间的桥：只开放一份白名单里的函数
app/shared/      后台和界面共用的类型和白名单（通道名、设置格式）
app/renderer/    界面（React）：看板、历史、各家表现、弹窗、设置
test/            各层的测试；test/ui/ 放界面测试，test/e2e/ 放整个应用的冒烟测试
```

**核心只有一份，命令行和应用都只是它的“外壳”。** 规则只写在核心里，比如推理强度的限制、额度拦截、自检拦截、只能在锁里改任务记录。两个外壳里都不重复写。

## 4. 数据怎么流动

- **读**：应用后台监视 `~/.xagents/`（或 `XAGENTS_HOME`），有变化时等 0.3 秒，把连续的几次变化合成一次，再用核心的 `buildView()` 读登记处，拼成界面要的数据（`View`，类型在 `src/core/view-types.ts`），推给窗口。
  - 窗口不读文件。旧网页版的 `data.js` 汇总已随网页一起下线。
- **写**：窗口里点按钮 → 通过桥调用白名单里的一个函数 → 后台先检查参数，再调核心 → 核心在锁里改任务记录 → 登记处有变化 → 窗口自动更新。
  - 应用和命令行同时改同一条任务也不会乱，因为核心本来就有锁。
- **额度**：打开窗口时查一次，之后每 15 分钟查一次，都在后台跑，不卡界面（细节见第 6 节）。
- **自检**：沿用核心的规则，一天之内有效。窗口右上角显示结果。

## 5. 界面

界面规范（颜色、字号、间距、统一部件、文案、顶栏、设置页）以 [ui-spec.md](ui-spec.md) 为准，改界面先看它。这里只写应用层面的行为：

- **窗口**：
  - 标题栏和内容融为一体，Mac 左上角的三个按钮照常保留；
  - 深浅色跟随系统；
  - 记住窗口大小和位置（存在 Electron 用户数据目录的 `window.json`）；
  - 关窗口只是隐藏，从菜单栏图标或程序坞再打开；退出用菜单栏或应用菜单里的“退出”。
- **弹窗只给主人看人话**（人只需要关心进度）：
  - 要做什么：负责人派活时写给主人的一两句大白话（`summary`）；
  - 进展：只在还在跑时显示，是选手最近的动作；
  - 结果：负责人验收后的结论，或者“负责人还在看”。

  选手报告、代码改动、写给选手的题目原文都是负责人工作用的，不放进应用。
- **弹窗里的按钮**：
  - 做完、还没拍板：“用这份”“不要了”；
  - 失联或出错：“重做”“不要了”；
  - 还在跑：“停下”；
  - 一批活：每家一个“用这份”，另有一个“都不要”。

  主人点的按钮只记下决定，由负责人下次查看时照办（`xagents inbox`）。“不要了”和“停下”要二次确认，确认框里写清楚后果。
- **给负责人留言**：单家弹窗底部有留言框（⌘ 回车发送），往来留言按时间排在上面；有留言等负责人回复时，卡片角上有一个小圆点。负责人用 `xagents reply` 回复，会弹系统通知；负责人在后台 `xagents wait` 时，主人一留言就会被提前叫醒（约定见第 10 节）。
- **快捷键**：
  - ⌘1、⌘2、⌘3：切换看板、历史、各家表现；
  - ← →：弹窗里切换上一张、下一张；
  - Esc：关闭弹窗；
  - ⌘R：立即刷新；
  - ⌘,：打开设置。
- **菜单栏图标**：
  - 图标旁边显示在跑的数量；
  - 下拉菜单列出在跑的活（谁、做什么、做了多久）和验收中的活，点任何一条都会打开主窗口，并直接弹出那一条。
- **系统通知**：
  - 什么时候发：负责人拍板采用或放弃，以及负责人回复了主人的留言；
  - 同一件事只通知一次（已通知的事件记在用户数据目录的 `notification-events.json`）；
  - 可以在设置里关掉，关掉期间发生的事不会在重新打开后补发。
- **设置**：两栏设置窗口（左边分页，右边内容），窗口右上角有设置按钮，也可用 ⌘, 或应用菜单里的“设置…”打开。分页有通用（外观、防休眠、系统通知、开机自动启动、存储）、选手与模型（最上面是派活限制）、看板颜色、接入 AI（给其他 AI 的对接提示词，一键复制），细则见 [ui-spec.md](ui-spec.md) 第 10 节。选手与模型的规则由核心强制执行，见 [design-commander.md](design-commander.md) 的 3b。
- **各家图标**：安装时从本机已装的应用里导出，放在 `~/.xagents/icons`，不打进安装包，也不进仓库；缺图标时退回字母圆标。
- **派活工作台自己的应用图标**：原创设计，源文件 `build/icon.svg`，打包使用 `build/icon.icns`；负责人已制作，`npm run icon` 可重新生成。

## 6. 安全（按正式产品的要求）

- **窗口进程**：
  - 开启隔离（`contextIsolation`、`sandbox`），关闭 Node 能力（`nodeIntegration: false`）；
  - 只加载应用自带的页面，禁止跳转和打开新窗口；
  - 外部链接一律交给系统浏览器打开。
- **严格的内容安全策略**：
  - 页面只能加载自己的脚本和样式，不允许内联脚本，不允许远程资源；
  - 图标通过应用自己的只读协议（`xa-icon`）提供，只能读图标目录。
- **桥**：
  - 只开放白名单里的少数函数（通道见 `app/shared/ipc.ts`），每个参数都先检查格式和范围，比如任务号必须是登记处里真实存在的；
  - 窗口不能拼出任意文件路径或命令。
  - **接入 AI**：`connectStatus()`（`xa:connect-status`）不收参数；`connect(ai)` / `disconnect(ai)`（`xa:connect` / `xa:disconnect`）只收一个 `claude|codex|grok|cursor` 名字。三个处理先校验来源窗口，再调核心，返回四家状态；窗口不直接碰文件。
  - **复制对接提示词**（通道 `xa:copy-intro`）：校验来源窗口，不收参数（桥也不往后台传参数），后台用 Electron 的剪贴板写入 `src/core/intro.ts` 那一份固定内容；窗口本身的一切权限请求仍然全部拒绝。
  - **刷新额度**（通道 `xa:quota-refresh`）也登记在白名单里：校验来源窗口，不收任何参数；同一时间只跑一次，两次之间（从上一次结束算）至少隔 60 秒，刚刷新过或正在刷新时直接拒绝并说明原因。
- **选手的动作原文**：一律当文字显示，不当网页代码插入。
- **应用自身**：
  - 不开端口，不联网；
  - 不读 `~/.ssh`、各家登录文件、设置里额外禁读的目录；
  - 查额度时调用的是各家自己的程序，读取方式和命令行版完全一样；
  - 刷新额度由主进程调用核心现有的额度查询（和 `xagents quota` 是同一个函数，不另写一份）。它会启动各家命令行去查，联网的是那些命令行自己，**应用本身仍然不开端口、不直接联网**；
  - 应用开着时每 15 分钟自动刷新一次（启动时数据已超过 15 分钟也刷一次），“各家表现”页也有手动“刷新”按钮，走上面的同一条通道；
  - 某一家这次查不到时，保留那一家上一次的数据和时间，并写“这次没查到”，不清空。
- **打包与安装**（2026-09-30，脚本已实现，待真实环境验收）：
  - 依赖用 `pnpm install --offline --frozen-lockfile` 安装。`package.json` 是唯一打包配置：`appId` 为 `app.xagents.desk`，`productName` 为“派活工作台”，图标为 `build/icon.icns`，只出 macOS arm64 的目录，不出安装镜像。
  - `npm run pack` 先构建，再检查主进程、预加载的外部依赖，最后生成 `dist/mac-arm64/派活工作台.app`。应用只带 `out/**`、`package.json` 和 `src/core/pty-bridge.py`；明确排除 `node_modules`，包含 pnpm 软链接背后的依赖，不带界面已打包的 React 和桌面不使用的 sandbox-runtime。
  - `pty-bridge.py` 用 `asarUnpack` 放在 `app.asar.unpacked`；`toolRoot` 仍指向 `app.asar` 内部，额度查询通过核心 `unpackedPath()` 得到 Python 能直接读取的真实文件路径。
  - 访达打开时，桌面入口把存在的 `~/.local/bin`、`~/.grok/bin`、`/opt/homebrew/bin`、`/usr/local/bin` 补到 PATH 末尾，保留原优先级且不重复。不会执行登录 shell，命令行版不调用这个补全。
  - `npm run install-app` 依次打包、本地签名、严格验签、退出开发版和已装版、把旧 `/Applications/派活工作台.app` 移到废纸篓的唯一目录、用 `ditto` 安装、再次验签、打开应用。任何一步失败立即停并用中文说明；旧进程 10 秒内不退出也停止，不强杀、不删除旧应用。
  - builder 配置 `identity: null`，由安装脚本运行 `codesign --force --deep --sign -` 做本地签名，再用 `codesign --verify --deep --strict` 验证。
  - 应用继续使用 `~/Library/Application Support/派活工作台`，保留设置和窗口位置；收到安装脚本的退出信号也会保存窗口。登记处沿用 `~/.xagents`，定时清理仍走原来的核心逻辑，将旧日志移到系统废纸篓。
  - 隔离内不运行构建、打包、安装和窗口冒烟；负责人需记录包大小、核对依赖检查和签名结果，并从访达双击检查中文菜单名、额度刷新、设置与窗口位置、开发版和已装版不会同时运行。
  - 要发给别人时，再做开发者签名和苹果公证（算在“做成产品”那一步里）。
- **单实例**：同一时间只运行一个派活工作台。再次打开时，把已经开着的那个窗口带到前面。

## 7. 质量标准

- TypeScript 全部开启严格检查，界面和后台代码都不允许用“任意类型”（`any`）绕过检查。
- `npm run verify` 一条命令跑完全部检查：类型检查、核心测试、组件测试、构建、整个应用的冒烟测试。五项全过才能合并。
- **冒烟测试**（`test/e2e/smoke.ts`）：
  - 用一份临时的登记处（里面放一批假任务）和临时的用户数据，启动构建好的真实应用窗口；
  - 检查各列的数量、弹窗、上一张 / 下一张；
  - 点“用这份”和发留言，确认任务记录里真的写上了决定和留言；
  - 检查菜单栏图标、系统通知、安全设置、设置窗口；
  - 分别截浅色、深色和窄窗口的图，存进已忽略的 `test/e2e/artifacts/`，由负责人目视检查。
- **性能目标**（目前没有自动测试）：
  - 登记处里有 1000 条任务时，窗口打开不超过 1 秒；
  - 一次变化推到窗口不超过 0.5 秒；
  - 在跑的活每秒更新计时，不能让整个窗口重画。

## 10. 应用与命令行的共同约定（原 D3 约定）

原先为“核心 / 命令行”和“应用”两边同时开工写的约定，仍然有效的部分摘在这里；字段和函数的确切形状以 `src/core/job.ts`、`src/core/view-types.ts`、`app/shared/ipc.ts` 为准。

**主人只看三件事**，全部是人话：要做什么（`summary`）、进展（`activity`）、结果（负责人写的 `decision.note`，以及要不要主人拍板）。

**任务记录里和应用有关的字段**（完整字段表见 [design.md](design.md) 第 6 节）：
- `summary`：派活时必填，1–200 字；批记录也带同一句；
- `decision`：`kind`（`adopt` / `drop`）、`note`（≤200 字）、`at`、`by`（`owner` / `lead`，旧记录缺这项按 `lead`）、`handled`；
- `redo`：主人点了“重做”，`by` 只会是 `owner`；
- `sleeps`：运行期间电脑休眠过的时段；
- `comments`：往来留言，按时间先后排列。

**核心函数**（签名不许随意改，两边都调用）：
- `decide(id, kind, note, by)`（`src/core/decide.ts`）：记下采用或放弃。任务还在运行时拒绝；主人的决定已经存在时，主人不能再选；副本已清理不能采用。负责人后来对主人已拍的板补结论时，保留主人选的那一项并记上 `handled`。
- `requestRedo(id)`：记 `redo`，`by` 为 `owner`；只能用在已结束的任务上；负责人已有结论、或已有一条没照办的重做请求时拒绝。
- `markHandled(id)`：负责人照办后调用，主人的决定、重做和留言一起记上 `handled`（重复调用无害）。
- `addComment(id, text, by)`（`src/core/comments.ts`）：追加一条留言。`text` 去掉首尾空白后 1–500 字（按字符数），不许含控制字符（换行可以）；负责人留言时，此前主人的留言自动记上 `handled`。
- `readSettings()` / `writeSettings(patch)`（`src/core/settings.ts`）：读写 `config.json` 里的防休眠、通知、看板列颜色、选手策略；缺省防休眠和通知都是开。
- 以上都在锁里“读 → 改 → 原子写”；参数不合法（任务不存在、`kind` 不对、超长、含控制字符）就抛出中文错误。

**主人拍的板（`by: 'owner'`）不改变任务状态，也不做任何 git 操作**，只是记下来。

**留言怎么判定**：
- 待负责人回复（`awaitingReply`，卡片上的小圆点）：这件活最后一条留言来自主人，并且没有 `handled`；
- 主人留言待处理（`pendingComments`，`inbox` 和 `wait` 共用）：主人的留言里，没有 `handled`、也没有被之后的负责人留言回复过的；
- `xagents inbox` 除了主人的决定和重做，也列出待回复的留言并显示原文；`xagents reply` 以负责人身份追加留言。

**应用这一侧**：
- 通道 `xa:decide`、`xa:redo`、`xa:stop`、`xa:comment`：主进程校验来源窗口、任务号格式、任务确实存在、文本长度和字符，同一任务同时只处理一个请求；
- 通知：负责人回复了主人的留言（一条负责人留言紧跟在主人留言之后）时发系统通知，同一条回复只通知一次；设置里关了通知就不发；
- `View` 的每条任务带 `summary`、`decision`、`redo`、`sleeps`、`comments`（没有就是空数组）；顶层带 `settings`（防休眠、通知、选手策略）和按清单顺序的 `roster`。

**`xagents wait`：主人有新动作时提前叫醒负责人**：
- `wait <任务号或批号>` 除了等指定的活结束，同时盯住“待办”（和 `xagents inbox` 同一套判定，任何任务上的都算）；
- 开始等待之前已经在待办里的旧事项不触发；开始之后新出现的（新的留言、新的决定、新的重做）立刻返回，用人话打印哪件活、主人做了什么、留言原文；
- 退出码：`0` 活都做完了，`1` 有出错或失联的，`3` 主人有新动作。活先结束时以活结束为准，同时出现的新动作在输出里另外提示；
- 负责人处理完（`xagents reply` 或 `xagents handled`）后，这些事项不再出现在待办里，也不再叫醒；
- 实现在 `src/core/wait.ts` 的 `waitForJobs(id, io?)`，读取任务和睡眠都可以替换，测试不需要真的等时间。
