# Codex 接自定义接口时，活派不派得出去（2026-10-12）

给 [design-scan.md](../design-scan.md) 的规则二当依据。探针是 `scripts/probe/codex-endpoint.mjs`，想重测：`node scripts/probe/codex-endpoint.mjs <codex 可执行文件> <结果文件>`；Windows 上由流水线 `.github/workflows/windows-probe.yml` 跑。

## 怎么测的

全程不碰真实的登录，不连真的接口：

- 本机起一个假的模型接口（只认 Responses 协议）。第一问回“请跑这条命令”，带着命令结果的第二问回一句话收尾，这样命令是在真正的 `codex exec` 隔离里跑的。
- 一个空的临时 Codex 文件夹当“用户的 Codex”：里面存一把假钥匙（`codex login --with-api-key`，明写存成文件），配置文件里写着接这个假接口，另外带两样**会在隔离外执行程序**的东西：任务结束时的通知程序、一个外部连接。它们一旦被执行就留下记号。
- 启动参数照抄 `src/core/workers.ts` 里派 Codex 活的那一行（权限表、环境变量规则直接用仓库里的函数生成），环境用 `workerEnv` 过滤。
- 隔离里跑的命令试五件事：写副本、写任务临时目录、写家目录、连外网、连本机端口，并列出看得到的名字带密钥字样的环境变量。

另外：

- `codex login status` 对钥匙登录报 “Logged in using an API key - sk-…”（钥匙只露头尾）。
- `codex debug models` 带着自定义接口时**不去问接口**，列的还是程序自带的 11 个模型。
- 这一版 Codex 发请求时不再用顶层的 `tools`：工具清单放在输入里的 `additional_tools` 项，跑命令要经一个叫 `exec` 的“写一段脚本”工具，脚本里再调 `tools.exec_command`。这和派活无关，但说明接口那一头必须跟得上 Codex 的版本；跟不上是接口的事，平台管不了。

## 结论

**成立的：**

1. **设计稿第 1 节的推断属实**：现在的启动参数下，接自定义接口的人派不出 Codex 的活。
2. **规则二的做法可行**：`--ignore-user-config` 不动，另用 `-c model_provider="<名字>"` 和 `-c model_providers.<名字>={…}` 把那一段带进去，活就能派。钥匙是 Codex 主程序自己从登录文件里取的，平台没有碰。
3. **原来挡住的一项没松**：用户配置里会在隔离外执行程序的两样东西仍然不执行（对照组证明探针测得出来）；隔离里的命令照旧只能写副本和任务临时目录，连不了外网和本机端口。
4. **带整张提供方表，不要只带 `openai_base_url`**：后者能通，但每次先白试 7 次长连接。

**钥匙放在环境变量里的人（主人 2026-10-12 定：放行点名的那一个，下面的“乙”）。**

配置里写 `env_key` 的人，钥匙在一个名字带 KEY 的环境变量里，平台现在会把它滤掉，活派不出去。实测：只把**这一个**变量交给 Codex 主程序时，活能派，而且选手跑的命令里仍然看不到它（Codex 自己那一层 `shell_environment_policy` 挡住了）。两种处理：

- 甲：照设计稿原来写的，不放开，派活时提示主人“把钥匙交给 Codex 自己保管”（`codex login --with-api-key`）。
- 乙：配置里点名的那一个变量放行给 Codex 主程序，其余照旧过滤；自检加一条“放行的变量在命令里看不到”。

**没测的：** 真的接口（各家转发服务对 Codex 新请求格式的支持程度不一）；联网总开关打开时的情况（权限表多一句允许联网，和连哪个接口无关，按理不受影响）。

## 独立审查后收紧的几处（2026-10-12）

另一家模型独立审了实现（构造了三十多份刁钻的配置去跑），结论是带进参数的东西逃不出“连哪个接口”这一段，钥匙的值不进启动参数和任务记录。它指出、已经照改的：

- 配置里点名放钥匙的变量如果是系统或平台自己要用的（`PATH`、`HOME`、`TMPDIR`、`CODEX_HOME` 这类），不带，并说明原因；平台给选手设好的值、这件活点名不要的变量，点名放行也盖不掉。
- 地址里自带账号密码、或地址参数的名字像钥匙的，等于把钥匙写在了配置里，不带（启动参数会写进任务记录）。
- 同一项写两遍，不猜哪个算数，当作读不懂。
- 续接（群、小队的下一轮）时“不给命令的变量名单不许变松”的那道核对，一直按错的参数名在筛，等于没做；改对了。现在主人中途换了放钥匙的变量，下一轮会被拒绝，换一位新成员。
- “变量名不带密钥字样时，点名之后命令是不是真的看不到”原先没有实测，补进了探针（上表最后一行）。

**知道就行的一点**：连哪个地址、把哪个变量当钥匙发过去，都由主人的 Codex 配置说了算。能改这份配置的人，可以让 Codex 把主人环境里的某个变量发到他指定的地址。这和主人自己在终端里用 Codex 是同一个风险，平台没有让它变大，也没法替主人挡；选手改不了这份配置（各家全局配置对选手只读）。

## Windows 流水线的结果

三台机器逐项一致，结论和 macOS 相同：

| 情况 | 活做完了吗 | 请求到了假接口吗 | 通知程序、外部连接 |
|---|---|---|---|
| 现在的启动参数 | 没有，约 20 秒后失败 | 没到 | 都没执行 |
| 另用 `-c` 带上那一段 | 做完了，3–4 秒 | 到了，带的是登录文件里的钥匙 | 都没执行 |
| 对照：读用户配置 | 做完了 | 到了 | 都被执行了 |
| 只带 `openai_base_url` | 做完了，约 9 秒 | 到了（先白试 7 次） | 都没执行 |
| 钥匙在环境变量、交给主程序 | 做完了 | 到了，带的是环境变量里的钥匙 | 都没执行 |
| 钥匙在环境变量、按平台过滤 | 没有，立刻失败 | 没到 | 都没执行 |
| 钥匙变量的名字不带密钥字样、点名不给命令 | 做完了 | 到了，带的是环境变量里的钥匙 | 都没执行 |

隔离里的命令：副本和任务临时目录写得进，家目录写不进，外网连不上。有两处和 macOS 不同，都和“连哪个接口”无关（带不带那一段、读不读用户配置，结果一样）：

- **本机端口连得上**。这是已知的：Codex 自己没拦住，要靠平台另装的那一层（[design-windows.md](../design-windows.md) 4.7），这个探针只装了 Codex 自己的隔离，没装那一层。
- 最后一行的那个变量，命令里**看不到**；对照的那个看得到。和 macOS 一样。
- **命令里看得到 `GIT_CONFIG_KEY_0`、`GIT_CONFIG_KEY_1`**。这是 Codex 的 Windows 隔离自己加的 git 设置项的名字，不是主人的变量；探针放的那把环境变量钥匙在命令里看不到。
