# 探针：Windows 上不启动 PowerShell，直接调系统接口

**日期：** 2026-10-13
**对应设计：** [design-windows.md](../design-windows.md) 第 13 节
**探针：** `scripts/probe/windows-native.mjs`；流水线 `.github/workflows/windows-probe.yml` 的 `native` 任务和 `.github/workflows/build.yml` 的“System calls without PowerShell”一步

## 要回答的问题

平台有三处在后台启动系统自带的 PowerShell（防休眠、读进程列表、送进回收站），杀毒软件会把“程序隐藏执行 PowerShell”拦下来。改成用 `koffi` 直接调系统接口：

1. 这个模块在平台的 Node 里、在应用自己的程序（以 Node 方式运行）里，装不装得上。
2. 三件事做不做得成，结果和原来的做法是不是一样。
3. 没有管理员身份时还行不行。

## 环境

| | |
|---|---|
| 机器 | 流水线的 `windows-2022`（x64）、`windows-2025`（x64）、`windows-11-arm`（ARM64） |
| Node | 24.21.0 |
| 应用自己的程序 | Electron 44.4.5（`windows-2022` 上打的安装包，装到用户自己的程序目录后跑） |
| koffi | 3.3.2，用随包发的编译产物，安装脚本没有运行 |
| 身份 | 每台机器两遍：流水线缺省的管理员身份；用 `runas /trustlevel:0x20000` 去掉管理员权限（令牌里管理员组变成“只用于拒绝”）再跑一遍 |

## 结果

三台机器、两种身份、外加装好的应用，结论一致。

### 加载

都装得上。应用自己的程序里也一样（从装好的应用的 `resources/platform/node_modules/koffi` 加载）。

### 防休眠：`SetThreadExecutionState`

用 `powercfg /requests`（系统的“谁在申请别休眠”名单，要管理员身份才读得了）核对：

| 步骤 | 名单里有没有这个进程 |
|---|---|
| 申请之前 | 没有 |
| 另一个进程申请以后 | 有 |
| 那个进程被直接结束以后 | 没有 |
| 自己申请以后 | 有 |
| 自己撤掉以后 | 没有 |

没有管理员身份时名单读不了，只核对了申请和撤销的返回值，系统都接受。

### 读进程列表：`NtQuerySystemInformation`

和原来的做法（PowerShell 读 `Win32_Process`）同一时刻各读一次，逐条对进程号、父进程号、创建时间（毫秒）：

| 机器 | 身份 | 对过的条数 | 不一样的 | 新做法耗时 | 原做法耗时 |
|---|---|---|---|---|---|
| windows-2022 | 管理员 | 128 | 0 | 2 毫秒 | 3.7 秒 |
| windows-2022 | 去掉管理员权限 | 130 | 0 | 2 毫秒 | 0.3 秒 |
| windows-2025 | 管理员 | 147 | 0 | 2 毫秒 | 2.3 秒 |
| windows-2025 | 去掉管理员权限 | 150 | 0 | 2 毫秒 | 0.3 秒 |
| windows-11-arm | 管理员 | 150 | 0 | 3 毫秒 | 6.0 秒 |
| windows-11-arm | 去掉管理员权限 | 154 | 0 | 2 毫秒 | 0.4 秒 |
| windows-2022，装好的应用 | 管理员 | 126 | 0 | 3 毫秒 | 0.3 秒 |

只在原做法里出现的两三条，是为了这次读取才起的 PowerShell 自己。探针另外起了一棵三层的进程树（父、子、孙）：三个进程新做法都读得到，父子关系对，创建时间和原做法一毫秒不差，并且落在起它们的那一刻附近（平台认进程用的就是这个时间窗）。

### 送进回收站：`SHFileOperationW`

名字里带中文和空格的文件夹（主人在回收站里看到的就是这种名字），新旧做法各送一个：

| | 新做法 | 原做法 |
|---|---|---|
| 返回 | 0（成功） | 退出码 0 |
| 原处还在不在 | 不在 | 不在 |
| 这个盘的回收站目录里，当前账户的条目 | 多一条 | 多一条 |

不存在的路径：返回 2，不弹窗、不卡住。

流水线的机器上用外壳的接口列回收站，新旧做法都列不出东西（这种机器没有桌面会话），所以改成直接数回收站目录里的条目。

## 结论

- 三件事都不用启动别的程序就做得成，结果和原来的做法一致，不要管理员身份。
- 读进程列表快了两到三个数量级。
- 结构体按 64 位系统取数，x64 和 ARM64 一样；32 位的 Windows 不支持（平台本来也不出 32 位的包）。

## 没验的

- 杀毒软件：流水线的机器上只有系统自带的那一种。火绒、360 对“程序加载一个没有签名的模块”有没有提醒，没有验。
- 真正的普通账户（不在管理员组里的）：只验了“管理员组被去掉权限”的令牌。
