# Windows 上 Codex 自带隔离的实测（2026-10-12）

给 [design-windows.md](../design-windows.md) 第 4 节当依据。探针是 `scripts/probe/windows-codex.mjs`，由流水线 `.github/workflows/windows-probe.yml` 在三台真的 Windows 机器上跑；想重测，把代码推到公开仓库名字以 `probe/` 开头的分支，结果在这次运行的附件里。

## 在哪测的

| 机器 | 系统 | Codex |
|---|---|---|
| GitHub 托管，`windows-2022` | Windows Server 2022（10.0.20348），x64 | codex-cli 0.162.1（官方安装脚本，固定版本） |
| GitHub 托管，`windows-2025` | Windows Server 2025（10.0.26100），x64 | 同上 |
| GitHub 托管，`windows-11-arm` | Windows 11 企业版（10.0.26200），arm64 | 同上 |

三台都是管理员账户、没有登录 Codex、Windows 防火墙三个配置文件都开着。**三台的结果逐项一致**，下面不再分开写。

没测的：真的让模型干活（要登录）；主人自己的电脑（普通账户、会弹管理员确认框、装了杀毒软件和代理软件的环境）。

## 怎么测的

1. 外面先准备：一个当“副本”的目录、一个当“任务临时目录”的目录、家目录里一个普通文件和一个“密钥”目录、盘符根下三个分别允许“所有人 / 已登录用户 / 本机用户组”修改的文件夹、凭据库里一个随机名的测试条目、几个本机监听口和一个命名管道、一个名字带 KEY 的假环境变量。
2. `codex sandbox setup --elevated --current-user` 装隔离。
3. 用 `codex -c windows.sandbox="elevated" sandbox -P <权限表> -C <副本> -c <权限表内容> -c <环境变量规则> -- node <探针>` 在隔离里跑探针。权限表 `xa` 和 macOS 上同一个思路：继承 `:workspace`（只读题继承 `:read-only`），“密钥”目录禁读，系统临时目录只读，任务临时目录可写；`TEMP`、`TMP` 指向任务临时目录。
4. 对照组：同一份探针在隔离外跑一遍（每一项都通，说明探针本身没问题）。

## 结论

**成立的**（可以写进启动参数）：

- 管理员装一次的那种隔离，命令确实换成专用的低权限账户来跑；允许联网时换成另一个专用账户。
- 只能写副本和任务临时目录；只读题连副本也写不进。
- 权限表里逐个路径禁读是生效的。
- 外网被拦；允许联网的开关生效。
- `shell_environment_policy.exclude` 生效：不带这条规则时，隔离里看得到主人的密钥变量；带了就看不到。和 macOS 上一样，这条必须带，外面那一层过滤也照做。
- 专用账户看不到主人凭据库里的条目，连不上隔离外进程开的命名管道。
- 只允许“已登录用户”或“本机用户组”修改的文件夹，隔离里写不进。

**不成立的**（和底线有出入，见设计文档 4.6）：

1. **本机端口没拦住。** 隔离里连得上本机任何监听口，也能自己开监听口。Codex 装了一条“拦本机回环 TCP”的防火墙规则（规则存在、已启用，方向是出站，远端地址是回环段，端口 1–65535），它自己的冒烟测试也期待直连本机被拦；但三台机器上实测都没拦住。Codex 另外装的 12 条系统过滤规则只管 ICMP、DNS 和文件共享端口，不管回环。这和“联网开关关着时不给选手开本机端口”这条底线直接冲突：本机常有代理软件、浏览器调试口在监听，连得上代理就等于能上外网。
2. **允许“所有人”修改的文件夹挡不住。** Codex 官方文档自己也这么写。
3. **家目录下的东西默认读得到**（应用数据目录、存凭据的系统文件夹都列得出）。所以和 macOS 一样只能靠名单逐个禁读，名单要按 Windows 的位置重写。存凭据的文件夹里的内容是按账户加密的，专用账户解不开，但名单上仍然要列。

**另外查到的**：

- **每个 Codex 文件夹要各装一次。** 换一个空的 `CODEX_HOME`（DeepSeek 就是这样用的），隔离直接报错（“Restricted read-only access requires the elevated Windows sandbox backend”）；对这个文件夹再跑一次安装命令就好了，先前那个文件夹不受影响。两个文件夹共用同一对专用账户。
- **不先装就用**：流水线的机器上不会弹窗，它会自己装（约 5 秒），但这第一次运行会失败（隔离里的进程看不了家目录下的 `AppData`）；明确装过之后再跑就正常。主人的电脑上这一步会弹管理员确认框，所以要先装、再派活。
- **明写另外两种隔离做法没有起作用**：装过以后，启动参数里写“免安装的那种”或什么都不写，实际跑的仍是专用账户。我们只认专用账户这一种，自检要核对隔离里的身份确实是它。
- **隔离里查不了“当前用户是谁”**：Node 的 `os.userInfo()` 在专用账户下报错。依赖它的工具可能出错，要在真的项目上再测。
- 隔离里 `USERPROFILE` 仍然指向主人的家目录，`TEMP`、`TMP` 按我们给的走。
- 装隔离不到 2 秒；每条命令进隔离多花 0.3–0.5 秒。
