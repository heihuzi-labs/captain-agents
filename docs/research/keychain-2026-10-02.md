# 隔离里读系统钥匙串：实测与修法（2026-10-02）

起因见 [connect-deepseek-2026-10-02.md](connect-deepseek-2026-10-02.md) 第 5 节：Grok、Cursor 跑的 srt 隔离里能用 `security find-generic-password -s <名字> -w` 读出主人存进登录钥匙串的密码，违反“不让选手读密钥”。

环境：macOS 15.7.3，srt（`@anthropic-ai/sandbox-runtime`）0.0.77，Codex 命令行 0.159.0，Grok 命令行 1.0.46，cursor-agent 2026.10.01-14929f9。

测试全程用自己临时建的钥匙串条目（随机名、32 位随机值，用完删掉），只看退出码和读出的字符数，不读、不打印任何真密码。

## 1. 结论

- **修法**：三种隔离都禁读两个钥匙串文件夹：`~/Library/Keychains`（本用户的，登录钥匙串在这里）和 `/Library/Keychains`（系统的）。Grok、Cursor 写在模板 `sandbox/*.json` 的 `denyRead` 里，Codex 写在权限表里（`sandbox.ts` 的 `keychainDirs`）。挡住后 `security` 读不出、也列不出条目。
- **Cursor 的登录本来就放在钥匙串里**，挡住后它会报没登录。改成：看管进程启动 Cursor 前在隔离外读出 Cursor 自己的登录令牌，只放进这次 Cursor 进程的环境（`CURSOR_AUTH_TOKEN`），不写进任务记录；再设 `AGENT_CLI_CREDENTIAL_STORE=memory` 让它只在内存里记登录、不去写钥匙串。派 Cursor 活前也先在隔离外查一次（没登录或剩不到 2 小时就不派）。
- **Grok** 的登录在 `~/.grok/auth.json`，不用钥匙串；挡住后照常启动、联网、跑命令。
- **Codex** 的隔离本来就读不到（它不放行钥匙串服务）；禁读两个文件夹是为了三家做法一致，之前 Codex 隔离里能列出这两个文件夹。
- 自检新加三项探针，三种隔离都要挡住；探针做法改了，缓存版本升到 5。
- 没有放宽别的隔离。

## 2. 原因

srt 0.0.77 生成 macOS 隔离配置的函数（`dist/sandbox/macos-sandbox-utils.js` 的 `generateSandboxProfile`）固定写着：

- `(allow mach-lookup ... (global-name "com.apple.securityd.xpc") ...)`
- `(allow mach-lookup (global-name "com.apple.SecurityServer"))`

钥匙串的密码由 `SecurityServer`（securityd）解密，但钥匙串文件是由调用方自己读的。srt 默认不禁读家目录，所以隔离里的 `security` 读得到 `~/Library/Keychains/login.keychain-db`，再请 securityd 解密。用 `security add-generic-password` 存的条目默认只信任 `/usr/bin/security` 自己，所以隔离里调 `security` 读，**不弹窗**就能拿到。

## 3. 找过的办法

| 办法 | 结果 |
|---|---|
| srt 的开关 | 没有。`network.allowMachLookup` 只能多放行；设置里的名字、路径都经 `JSON.stringify` 转义，插不进“收回”的规则。0.0.78（当时最新）这两处一模一样。 |
| 在 srt 外面或里面再套一层只挡钥匙串服务的 `sandbox-exec` | 不行。两种套法都报 `sandbox-exec: sandbox_apply: Operation not permitted`（macOS 不许给已在隔离里的进程再套一层）。单独一层（不套 srt）确实挡得住，但没法和 srt 叠用。 |
| 改 srt 的代码（打补丁） | 不采用：升级就悄悄丢，且要改第三方代码。 |
| **禁读钥匙串文件夹（采用）** | srt 的 `filesystem.denyRead` 本来就支持，挡得住，见下。 |

## 4. 实测：挡没挡住

命令：`out=$(/usr/bin/security find-generic-password -s <测试条目> -w); echo "rc=$? len=${#out}"`；列系统钥匙串：`security dump-keychain /Library/Keychains/System.keychain | grep -c '^keychain:'`。

| 在哪跑 | 读测试条目 | 列系统钥匙串条目 |
|---|---|---|
| 隔离外 | rc=0 len=32 | 95 条 |
| Codex 隔离（改前、改后一样） | rc=44 len=0（SecKeychainSearchCreateFromAttributes 参数无效） | 0 |
| srt 原模板 | **rc=0 len=32（读出来了）** | 95 条 |
| srt + 禁读 `~/Library/Keychains` | rc=44 len=0 | 95 条 |
| srt + 再禁读 `/Library/Keychains`（采用） | rc=44 len=0 | 0 |

系统钥匙串里是 Wi-Fi 等条目，读内容要管理员密码（会弹系统窗口），但条目名能直接列出；禁读后两样都没有了，也就不会被诱导弹窗。

另用一个没签名的小程序（Swift，`SecItemCopyMatching`，只要条目属性、不要密码，所以不会弹窗）查：

| 在哪跑 | 旧式钥匙串里的条目 | 新式（数据保护）钥匙串 |
|---|---|---|
| 隔离外 | 185 条 | 找不到（-25300） |
| srt 原模板 | 185 条 | 找不到 |
| srt + 禁读两处 | 找不到 | 找不到 |

新式钥匙串要靠程序签名里的权限才能查，没签名的程序在隔离外也查不到，所以 srt 放行的 `com.apple.securityd.xpc` 不构成新的口子。

**注意**：实测时曾用这个小程序直接读测试条目的密码，因为条目只信任 `security`，macOS 在主人桌面上弹了“是否允许访问钥匙串”的窗口（已立即停掉程序）。所以自检探针只用 `/usr/bin/security` 读测试条目，不用别的程序。

## 5. 实测：挡住以后各家还能不能干活

都在真实 srt 隔离里，用派活时同样的参数跑一个小题（“运行 cat a.txt，回复它打印的内容”）。

| 选手 | 原模板 | 禁读两处 | 禁读两处 + 交登录 |
|---|---|---|---|
| Grok（`grok-4.7` 中档） | 正常，读到 `hi` | 正常，读到 `hi` | 不需要 |
| Cursor（`claude-sonnet-5-5-medium`） | 正常 | **报错：Authentication required**（读不到钥匙串里的令牌） | 正常：跑了命令、联网、回复 `hi` |

- Cursor 的登录：cursor-agent 用 `/usr/bin/security find-generic-password -a cursor-user -s cursor-access-token -g` 读令牌（源码 `index.js` 的钥匙串类）。它认 `CURSOR_AUTH_TOKEN` 环境变量；只给这个时它会顺手往钥匙串存一份，存不进就打印“钥匙串条目卡住了，请删掉重登”的吓人提示（但照常干活）。再加 `AGENT_CLI_CREDENTIAL_STORE=memory`（源码 `credential-store.ts`，可选 `file`、`memory`）后只在内存里记，没有任何提示。
- 令牌有效期：当时的令牌约 57 天后才过期。普通登录时 Cursor 只在剩不到 5 分钟时才换新（换新还要 API 钥匙），干活中途不会换；所以派活前查一下，剩不到 2 小时就不派，请主人在终端运行 `cursor-agent login`。
- 从钥匙串读 Cursor 登录时，“没有这一项”（退出码 44）才说没登录；超时、启动失败、别的退出码说“读没成功，请重试”，不冒充没登录。
- Grok 有一次报 `Couldn't set model 'grok-4.7': Invalid params`，同一时刻它在刷新登录文件；随后原模板和新模板各重跑都正常，属偶发，与本修改无关。
- Cursor 在 srt 里本来就会打印 `failed to copy trust settings of system certificate`（它读系统证书信任设置时被挡），改前就有，不影响联网。

## 6. 自检（`xagents selfcheck`）

新加三项，三种隔离都要“挡住”：

- `keychain`：自检前在隔离外往登录钥匙串放一个测试条目（随机名、随机值，不带 `-A`/`-T`，只信任 `security`），读回核对一致才用；探针在隔离里用 `/usr/bin/security` 读它，只比对是不是那个值、不打印。读出来算放行；`security` 跑起来但读不出算挡住；读出别的、超时、`security` 启动不了、条目没建成算拿不准。测试条目都用固定账号 `xagents-selfcheck`，自检前后各按这个账号清扫一遍（一条条删到“没有这一项”为止），上次被杀掉或超时后才写进去的也一并清掉；删不掉就记进自检结果、自检不过，不悄悄留下（2026-10-02 Grok 独立审查指出，已实测：放两条再清扫，剩 0 条）。
- `keychain-user`、`keychain-system`：列 `~/Library/Keychains`、`/Library/Keychains`，权限拒绝才算挡住。

改后实测（临时登记处，真实三种隔离）：

```
自检通过：目录外写、公用临时目录、硬链接、各家全局配置、Chrome 调试口、本机端口、外网、读密钥、登录文件和钥匙串都被挡住，副本内可写
codex  keychain=denied(security 退出码 44)  keychain-user=denied(EPERM)  keychain-system=denied(EPERM)
grok   keychain=denied(security 退出码 44)  keychain-user=denied(EPERM)  keychain-system=denied(EPERM)
cursor keychain=denied(security 退出码 44)  keychain-user=denied(EPERM)  keychain-system=denied(EPERM)
```

对照（临时换回原模板、去掉 Codex 的两条禁读，确认探针抓得住）：

```
codex  keychain=denied(security 退出码 44)  keychain-user=allowed  keychain-system=allowed
grok   keychain=allowed(读出了测试条目)     keychain-user=allowed  keychain-system=allowed
cursor keychain=allowed(读出了测试条目)     keychain-user=allowed  keychain-system=allowed
```

自检没过，派活被拦（`隔离自检没过，不能派活：…`）。两次自检后钥匙串里都没有留下测试条目。

## 7. 端到端派活

临时登记处、临时小仓库，`xagents run --ro` 同时派给 `cursor-grok:medium`、`grok:medium`、`codex:medium`，题目让它们 `cat hello.txt`，再跑上面的读测试条目命令：

- Cursor · Grok：17 秒完成，读到 `你好，派活`，钥匙串那行是 `rc=44 len=0`（靠平台交给它的登录正常干活）。
- Grok：18 秒完成，同样 `rc=44 len=0`。
- Codex：25 秒完成，读到文件；它自己判断不该读钥匙串，没跑第二条（隔离读不到已由自检证明）。
- 任务记录里 Cursor 那件只有 `"AGENT_CLI_CREDENTIAL_STORE": "memory"` 和 `"login": "cursor"`；在整个登记处里搜 Cursor 令牌原文，一处也没有；Cursor 的错误输出是空的。

## 8. 还留着的

- srt 仍放行 `com.apple.SecurityServer`：没有钥匙串文件就读不出密码，但别的安全接口（比如申请管理员授权的弹窗）还能调用。收不回，只能等 srt 加开关。
- Cursor 的活里，Cursor 自己的登录令牌在它的进程环境里，选手跑的命令看得到。这和改前“Cursor 必须读得到自己的登录”一样，没有变宽；别家的登录和主人的其他密码都读不到了。
- 禁读 `/Library/Keychains` 后，管理员自己装进系统钥匙串的根证书（比如公司代理的证书）在隔离里用不上；苹果自带的根证书在 `/System/Library/Keychains`，不受影响。实测 Grok、Cursor 联网正常。
