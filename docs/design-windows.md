**状态：** 主人 2026-10-12 点头，按第 7 节分步做。做到哪一步、实测出了什么，记在各步的探针报告里（`docs/research/`）。

## 1. 要解决什么

Windows 的安装包能打出来、应用能打开，但一件活也派不出去：隔离自检对非 macOS 直接返回“当前只支持 macOS 的实测隔离方式”，自检不过平台就拒绝派活。这个拒绝是对的——Windows 上确实没有任何一条隔离是实测过的——所以不能靠删掉判断来“修”，要把 Windows 上的隔离真的做出来、测出来。

做完的标准（主人定的）：

1. 真的 Windows 电脑上：隔离自检通过；真的派一件小活，选手在隔离里做完，验收通过。
2. `npm test` 在流水线的 Windows 机器上全过，并加回流水线。
3. 在线更新和“安装命令行”在 Windows 上要么能用，要么界面写明暂不支持，不留点了没反应的入口。
4. `release/config.json` 的 `targets` 加上 `win-x64` 之前，更新清单和发版脚本能处理 Windows 的安装包。
5. 文档里写着“只支持 macOS”的地方同步改掉。

## 2. 现状

### 2.1 仓库里只认 macOS 的地方（通读代码得出）

不只是隔离。按“改起来有多大”分三类：

| 类别 | 有哪些 |
|---|---|
| 改个写法就行 | 用 `/` 拼接和比较本机路径（动作记录、项目检查、运行包、删副本时比对 git 输出）；用 `:` 切 PATH；测试里写死的 `/repo`、`/tmp`、`core/roster.ts`；测试用 `HOME` 换家目录（Windows 上要同时设 `USERPROFILE`，**不改的话这些测试会读写真实的家目录**）；仓库没有固定换行的设置 |
| 要为 Windows 另写一套 | 跑验收和准备命令的外壳（现在是 `/bin/sh -c`）；停选手（现在靠“杀整个进程组”，Windows 没有这个概念）；防休眠（`caffeinate`）；废纸篓（`~/.Trash`）；找各家程序的位置；文件“先写临时文件再改名”和文件锁在 Windows 上遇到“文件正被别人打开”要重试；安装命令行（现在写的是 sh 脚本）；在线更新（现在只会换 `.app`）；托盘、标题栏、快捷键、通知 |
| 隔离和安全，必须真机实测 | 各家的隔离参数、自检的每一项探针、密钥变量过滤、登录文件怎么给、停选手后有没有残留进程 |

### 2.2 流水线上那次 Windows 测试（公开仓库 2026-10-11 的运行日志）

- 前 15 项里失败的 3 项都是路径写法：两项拿 `/repo` 这类路径当副本位置，Windows 上被解析成 `C:\repo` 后对不上；一项拿 `core/roster.ts` 和 Windows 的 `core\roster.ts` 比较。
- 卡死发生在第 16 项，`archive.test.ts` 的第一个测试：它真的派一件替身活再等它结束。最可能的原因：核心里跑外部命令的函数只在“输出管道关闭”时才算结束，而清理遗留子进程靠“杀整个进程组”，Windows 上这一步不起作用，于是一直等。**这是推断**，要在 Windows 机器上重跑才能确认。

## 3. 范围

### 第一步就要有

- **Codex 这一路能在 Windows 上派活**：Codex 的各个模型，加上借 Codex 跑的 DeepSeek。理由：三家里只有 Codex 自带的隔离官方支持 Windows；主人现在开着的选手也全是这一路的。
- 命令行能在 Windows 上装、能用（负责人就是靠命令行派活的，没有它等于没法派）。
- 核心测试在 Windows 上全过并回到流水线。
- 界面上凡是 Windows 还做不到的，写明“Windows 版暂不支持”，不留空按钮。

### 后做

- **在线更新**：第一步里 Windows 版显示“暂不支持在线更新，请到下载页装新版”（现在已经是这样）。做好之后再把 `win-x64` 加进发版目标。
- **Cursor**：等 Codex 这一路在真机上站稳了再做，而且**不保证做得成**，原因见 4.5。在那之前，Windows 上派 Cursor 的活会被平台拒绝，写明原因。
- 各家图标在 Windows 上从哪导出、托盘图标的细节。

### 不做

- **Grok**：主人 2026-10-10 定了不派 Grok，Windows 上不为它做隔离。Windows 上派 Grok 的活一律被平台拒绝。
- WSL：只做原生 Windows。
- Windows 安装包的代码签名：要买证书，是主人的决定，不在这次范围里（影响见第 9 节）。

**平台差异只写一处**：核心里加一张“这个平台支持哪几种隔离”的表（macOS：三种；Windows：先只有 Codex）。选手清单还是 `roster.ts` 那一张，不改；派活时多过一道“这位选手的隔离在本平台有没有”，自检只查本平台支持的隔离。这只会让能派的范围变窄，不会变宽。

## 4. 隔离方案

### 4.1 Codex 在 Windows 上的三种隔离，只有一种够得着底线

| 做法 | 怎么实现 | 能按名单禁读吗 | 断网 | 本机端口 | 结论 |
|---|---|---|---|---|---|
| 管理员装一次的那种 | 建专用的低权限本地账户来跑命令，文件权限划边界，防火墙规则按账户拦 | 能，逐个路径禁 | 防火墙拦掉对外连接 | 默认也拦（只放行它自己的代理口） | **用这个** |
| 免安装的那种 | 用主人账户派生一个受限的身份 | **不能**（官方明说） | 只靠环境变量约定，官方说“较弱” | 拦不住 | 不用：读不到密钥这条保证不了 |
| 微软新机制 | 进程级隔离，免管理员；只有较新的 Windows 11 才有 | 看系统支持不支持 | 拦对外 | **明确放行本机端口** | 不用：和“关着时不开本机端口”冲突 |

所以平台在 Windows 上**只认第一种**：启动 Codex 时明写用它，自检先核对它确实装好了；没装好就不派，不退到另外两种。

代价：主人的 Windows 电脑上要先装一次（会弹一次系统的管理员确认框）。这属于“本机系统弹窗”，只能主人自己点。派活工作台不替主人提权；第一步由自检报错里给出要运行的那一条官方命令，主人在终端里跑一次。

### 4.2 Codex 在 Windows 上的启动参数（全部待实测）

和 macOS 用同一套思路：平台自己的权限表 `xa`，不读主人的 Codex 配置，关掉插件、连接、钩子、记忆。Windows 上的差别：

| 项 | macOS 现在 | Windows 打算 | 为什么要重测 |
|---|---|---|---|
| 隔离做法 | 系统自带 | 启动时明写“管理员装一次的那种” | 源码显示：不写的话，“可写副本”会被**悄悄降成只读**，活做不了 |
| 权限表里的路径 | `/Users/…` | 盘符路径，反斜杠 | 写法不同；根目录、结尾斜杠的检查也要认盘符 |
| 临时目录 | 公用的 `/tmp` 和系统临时目录设只读，任务自己的 `tmp/` 可写 | 同样的意思：系统给用户的临时目录只读，任务的 `tmp/` 可写，`TEMP`、`TMP` 指过去 | `/tmp` 那一条在 Windows 上会被丢掉；临时目录按 `TEMP`/`TMP` 算 |
| 禁读名单 | 家目录下的密钥、登录、终端配置、凭据文件，加钥匙串 | 同名的照搬；另加 Windows 才有的位置（见 4.4） | 整盘禁读再逐个放行的写法在这种隔离上会被拒绝，只能“整盘可读 + 名单禁读”，和 macOS 一样是黑名单 |
| 联网总开关打开时 | 权限表里加一句允许联网 | 同样 | 打开后本机端口是否也放开，要测；即使仍然拦着也可以接受（更严） |
| DeepSeek | 单独的 Codex 文件夹 | 同样 | 隔离的“装好了”标记是按 Codex 文件夹分开存的，DeepSeek 那个文件夹可能要再装一次 |
| Codex 程序在哪 | 应用包里 | 官方安装脚本装的 `codex.exe`；只认 `.exe`，不认 npm 装出来的 `.cmd` 外壳 | Node 不能直接启动 `.cmd` |

每一条定下来之前都要有探针结果，写进 `docs/research/`，和 2026-09-29 在 macOS 上的做法一样。

### 4.3 底线逐条对照

| 底线（AGENTS.md） | Windows 上怎么保证 | 靠什么确认 |
|---|---|---|
| 自检没过不派活，`--force` 也跳不过 | 不变。非 macOS 直接拒绝的那一句，换成“跑 Windows 的探针” | 核心测试 + 真机 |
| 选手只能写自己的副本（外加任务的 `tmp/`） | Codex 权限表：副本和 `tmp/` 可写，别处不可写 | 探针：副本内写得进；家目录、公用临时目录、别的盘符根目录、各家全局配置都写不进 |
| 公用临时目录不许写 | 系统给主人的临时目录设只读；另查所有人共用的几处（见 4.4） | 探针 |
| 各家全局配置只读 | 都在副本外，默认写不进 | 探针：macOS 那 21 处的 Windows 对应位置，加各家程序的安装目录 |
| 读不到密钥和登录文件 | 权限表逐个禁读 | 探针：SSH、npm 登录、三家登录文件、DeepSeek 文件夹、终端配置和历史、常见凭据文件、系统凭据库 |
| 看不到带密钥字样的环境变量 | `env.ts` 那套规则不变（按名字过滤，本来就不分大小写）；Codex 自己那一层照带 | 探针：外面放一个假变量，里面必须看不到 |
| 联网只有一个总开关，关着时本机端口也不通 | 防火墙规则按专用账户拦 | 探针：外网、浏览器调试口、一个本机监听端口，直连和走代理都要被拒 |
| 不开本机套接字 | Windows 上对应的是“命名管道”（本机程序之间的通道，比如代理 SSH 密钥的服务、容器服务） | **新加探针**：连这类管道必须连不上 |
| 看管进程出错必须先停选手 | 停选手换成“停掉整棵进程树”，停完再核对一遍确实没剩 | 核心测试（Windows 流水线）+ 真机 |
| 干活的一方不提交 | 副本的提交记录库在副本外，写不进 | 探针：在副本里提交必须失败 |
| 桌面应用自己不开端口、不读密钥 | 不变 | 现有测试 |

### 4.4 Windows 上的自检要查什么

macOS 上现有的探针每一项都要有 Windows 的对应，不许少；Windows 特有的风险另加。结果的判定规则不变：该通的两项（副本内写、任务临时目录）必须通，其余必须被挡，拿不准也算不过。

- **照搬**（只换路径）：副本内写、任务临时目录、硬链接、家目录写、外网、浏览器调试口、本机监听端口（找监听端口的办法换成系统自带的命令）、SSH、npm 登录、三家登录文件、DeepSeek 文件夹、常见凭据文件、带密钥字样的环境变量、各家全局配置。
- **换成 Windows 的位置**：
  - 终端配置和历史 → PowerShell 的配置文件和命令历史（主人同样可能把钥匙写在里面）。
  - 钥匙串 → Windows 的凭据库：外面临时放一个测试条目，里面必须读不出；存凭据的几个系统文件夹必须列不出。
  - 公用临时目录 → 系统给主人的临时目录、Windows 自己的临时目录、所有用户共用的公共目录和程序数据目录、负责人会话的临时目录。
  - 各家全局配置 → 家目录下同名的那些，加各家程序在 Windows 上的安装目录。
- **Windows 新加**：
  - **开机自动运行的位置**（启动文件夹、PowerShell 配置文件）：选手写得进去，主人下次登录就会以自己的身份执行，等同逃出隔离。必须写不进。
  - **命名管道**：见上表。
  - **隔离装好了没有**：没装好时不跑探针，直接报“还没安装 Codex 的 Windows 隔离”，并给出那一条官方命令。

缓存版本号升一级；Windows 和 macOS 的结果分开判定，互不冒充。

### 4.5 Cursor：后做，而且可能做不成

Cursor 自己在 Windows 上没有隔离，只能靠 srt。srt 在 Windows 上的做法和 macOS 差别很大，有几处直接碰底线，**每一处都要真机探针，过不了就不开**：

1. **写限制是“另外加权限”，不是“默认全挡”**：一个文件夹如果本来就允许本机所有登录用户修改，专用账户照样写得进去（srt 的公开问题单，还没修）。
2. **本机命名管道没有拦**（同上，还没修）。
3. **专用账户打不开装在主人个人目录下的程序**：Cursor 正好装在那里，要另外放行。
4. **专用账户有自己的家目录，看不到主人的登录文件**：Cursor 的登录只能用环境变量传进去。这和 macOS 上“Cursor 读得到自己的登录”是同一范围，但做法不同，要重新核对它会不会把登录写到别处。
5. 查 Cursor 额度要模拟终端，现在的做法（Python 脚本）在 Windows 上不能用，要另找办法；找不到就只报“查不到”，不拦派活（和现在的规则一致）。

所以 Cursor 放在 Codex 站稳之后，单独立项、单独出探针报告、单独请主人点头。

### 4.6 现在就知道的短处

- **所有人都能写的文件夹，这类隔离挡不住**。Codex 官方自己也这么写。对策不是放宽：自检把常见的几处都查一遍，哪一处写得进去就判不过，并告诉主人是哪个文件夹权限太宽。
- **官方问题单里有几条还开着的故障**（0.162.1 上有人报“每条命令都报隔离刷新出错”“启动隔离进程被拒”）。真机上碰到了就如实报、不派活，等官方修或换版本，不绕。
- **装在主人个人目录下的工具（比如按用户装的 Node）专用账户能不能用，没查清**。用不了的话选手跑不了项目的测试，活就只能做到“写完代码、测试交给负责人在外面跑”。待实测。
- **路径太长**：Windows 默认路径上限约 260 个字符，副本在项目里的子目录下，再加上依赖目录，可能超。待实测，需要时给副本打开 git 的长路径开关。
- **流水线的 Windows 机器是服务器版系统，不是主人用的那种**。在上面测过只能说明“这套做法在一台真的 Windows 上成立”，不能代替主人电脑上的自检。好在自检本来就是每台电脑各跑各的。

## 5. 隔离以外要改的

| 块 | 做法 | 备注 |
|---|---|---|
| 平台差异集中 | 核心里新开一个文件，放“本平台支持哪些隔离、外壳怎么起、进程树怎么停、废纸篓在哪、各家程序在哪”。别处不再各写各的平台判断 | 规则只写在核心里，两个外壳不重复写 |
| 跑验收和准备命令 | Windows 上用 Git 自带的 `sh` 来跑（Git 本来就是必装的）。找不到就报清楚的错 | 好处：同一个项目登记的命令在两种电脑上写法一样。负责人定，主人可改 |
| 停选手和清理子进程 | Windows 上按进程树来停，停完核对没有残留；“请求停止”改成看管进程自己定时看到记号就收尾（现在靠发信号，Windows 上收不到），超时再强停。跑外部命令的函数补上兜底，不会再永远等 | 安全相关，不交给 Haiku |
| 文件写入和锁 | 改名遇到“被占用”时短暂重试；锁的回收逻辑在 Windows 上重新核对 | 多个进程同时读写任务记录是常态，Windows 上最容易出事 |
| 防休眠 | 用系统自带的 PowerShell 起一个小帮手，向系统申请“别休眠”，看管进程一退它就退 | 不加新依赖 |
| 废纸篓 | 移进 Windows 的回收站（同样用系统自带的 PowerShell） | “换掉的东西进废纸篓”这条规矩不变 |
| 安装命令行 | 在用户自己的程序目录里放两个启动文件：一个给 PowerShell 和命令提示符用，一个给 Git 的终端用 | 打算放在 Windows 默认就在搜索路径里的那个用户目录，这样不用改系统设置；这个目录是不是每台电脑都在搜索路径里，待实测 |
| 在线更新（后做） | 清单里 Windows 的包是安装程序；下载、核对大小和哈希的部分不变，“重启以完成更新”时静默运行安装程序再打开新版。发版脚本认 `.exe` | 见第 9 节关于签名的说明 |
| 界面（负责人自己做） | 标题栏给 Windows 右上角的三个按钮让位；快捷键同时认 Ctrl；托盘图标和数量提示按 Windows 的习惯；通知要登记应用标识才弹得出；设置里 Windows 做不到的入口写明“暂不支持” | 先改 `ui-spec.md` 再改代码；截图在流水线和真机上各看一遍 |

## 6. 哪些必须在真的 Windows 上测，怎么测

分两层，都由负责人组织，结果都写进 `docs/research/`：

**第一层：流水线的 Windows 机器（有管理员权限，没有任何登录）**

- 新加一个只能手动触发的探针流水线：装官方的 Codex、装它的隔离、用它“在隔离里跑一条命令”的调试命令跑我们的探针脚本，把结果存成附件。4.2 的每一个参数、4.4 的每一项探针，先在这里出第一轮结果。
- 同一台机器上跑核心测试和界面测试。
- 不登录就测不了的：真的让模型干一件活。

要在公开仓库上跑，所以用老办法：把文件树导出、推到公开仓库**单独的分支**（不带本机历史，不动公开仓库的主线），手动触发。探针流水线只读代码、不发布任何东西。**这一步是对外动作，要主人点头才做。**

**第二层：主人的 Windows 电脑**

1. 装应用、装命令行。
2. 装 Codex 并登录（主人做）。
3. 装 Codex 的 Windows 隔离（主人在弹出的管理员确认框上点“是”）。
4. 跑隔离自检，看每一项。
5. 派一件“往文件里写一句话”的小活，看它在隔离里做完；跑验收；看副本外有没有被动过、停止后有没有残留进程。
6. 界面截图：浅色、深色、窄窗口、弹窗。

第二层怎么操作由主人选（见第 8 节）。没在第二层跑过的，一律不写“已通过”。

## 7. 分几步交付

| 步 | 做什么 | 怎么算过 |
|---|---|---|
| 0 | 这份设计，主人点头 | 主人说行 |

| 2 | Codex 隔离：先出探针报告，再按报告写权限表、启动参数、Windows 自检 | 探针报告里每一项都有结果；流水线上跑真的自检通过（不是替身） |

## 9. 主人定的事

2026-10-12 主人定了前三条：

1. **范围**：第一步只做 Codex 这一路（含 DeepSeek），Cursor 后做且不保证做成，Grok 不做。
2. **公开仓库上可以开一个探针分支**跑 Windows 流水线（只多一个分支，不动主线，不发布）。
3. **主人电脑上的实测**：在那台电脑上开一个负责人会话来跑；登录和系统弹窗仍由主人自己点。
4. **Windows 安装包不签名**的影响，知道就行，现在不用定：用户第一次手动下载安装时，Windows 会弹“未知发布者”的提醒；应用内更新装什么，靠的是签名的清单加大小和哈希，这和 macOS 上一样牢（macOS 上现在的应用签名也只是本地签名，只能证明没被改过）。要去掉那个提醒得买代码签名证书。

## 10. 风险

- **官方的 Windows 隔离本身还在变**（早先的两个配置开关已经被删掉、换成了现在的写法）。对策：固定实测过的 Codex 版本号，自检每天重跑；版本变了探针不过就不派，和 macOS 上“各家程序自动更新，参数可能改名”是同一条规矩。
- **真机上某条底线就是做不到**。那就不开，写明原因，不放宽。最坏的情况是 Windows 版只能当看板用、派活仍然不行；这种情况会在第 2 步的探针报告里就暴露，不会拖到最后。
- **测试在 Windows 上会碰真实家目录**。第 1 步最先修这一条，修好之前只在流水线的机器上跑，不在主人的电脑上跑测试。
