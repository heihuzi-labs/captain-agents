# 选手模型自动发现 设计说明

**状态：** 实现中（2026-10-10 主人定）。
**起因：** 选手的模型写死在 `src/core/roster.ts`。2026-10-10 主人问“为什么是固定的、不是自动获取”，当场查到 Codex 的名单里已经多了 `gpt-6.1-sol`（官方说明“最新的主力模型”）而平台用不上。主人定：**自动发现；发现后由主人选保留哪些**。

## 1. 一句话

平台定期问各家程序“现在有哪些模型”；设置里每家多一个“管理模型”，主人勾选保留哪些；保留的每个模型就是一位选手，出现在“选手与模型”那张表里，照旧开关、选强度。底线照旧由平台套上，不因为模型是新发现的就放宽。

## 2. 概念

- **通道**：一种接法——用哪个程序、哪套隔离、强度怎么传、快速版怎么拼、扣哪个额度池。共四个：`codex`、`grok`、`cursor`、`deepseek`。通道写死在代码里（每条都有实测依据，见 design.md 第 7 节），**不自动发现**。
- **选手** = 通道 + 模型。选手号（`who`）：
  - 现有 8 位是“内置选手”，选手号不变（历史记录、打分、档案都按选手号记）：`codex`（gpt-6-astra）、`codex-luna`、`grok`、`cursor-grok`、`cursor-opus`、`cursor-sonnet`、`deepseek`、`deepseek-flash`。
  - 主人保留的新模型是“新增选手”，选手号 = `<通道>-<模型简写>`：模型名转小写，Codex 的去掉开头的 `gpt-`，其余非字母数字都换成 `-`，首尾和连续的 `-` 收掉。例：`gpt-6.1-sol` → `codex-6-1-sol`；Cursor 的 `gpt-6-astra` → `cursor-gpt-6-astra`。和内置选手是同一个（通道、模型）时用内置的选手号，不重复造。
- `Who` 从“写死的八选一”变成字符串；选手清单 = 内置 8 位 + 配置里的新增选手，进程启动时装载。

## 3. 发现（各通道怎么问、怎么收）

| 通道 | 怎么问 | 收哪些 | 强度 | 快速版 |
|---|---|---|---|---|
| codex | `codex debug models`（已有） | `visibility` 是 `list` 的；说明取 `description` | `supported_reasoning_levels` ∩ 中档、高档、超高档 | 不开（没核实官方文档，同现在） |
| grok | `grok models`（已有） | `grok-` 开头、不是 `-build-fast` / `-fast` 结尾的 | 中档、高档、超高档 | 名单里有 `<模型>-build-fast` 才有，启动名就是它 |
| cursor | `cursor-agent --list-models`（已有） | 只收 `claude-`、`gpt-`、`grok-` 三家；名单里一个模型按强度和快速版拆成多条（`<模型>-<强度>[-fast]`），合并回一个模型 | 出现过的强度 ∩ 中档、高档、超高档 | 出现过 `-fast` 才有，后缀 `-fast` |
| deepseek | 不问 | 仍是内置的两个 | 高档 | 没有 |

- DeepSeek 不自动发现：它的名单要带钥匙去问它的网站，平台自己不碰钥匙、不联网。
- 强度没有落在“中档、高档、超高档”里的模型不收（没法派）。
- 结果存 `~/.xagents/cache/models.json`：`{ at, channels: { <通道>: { at, error?, models: [{ model, shown, description?, efforts, fast }] } } }`。某一家没问到（程序没装、没登录、超时）：记下 `error`，保留上一次的名单，不影响别家。
- 什么时候问：桌面应用打开时如果上次是 24 小时前；之后每 24 小时；主人点“刷新”（一分钟内不重复问）；`xagents models refresh`。派活时**不问**，只读缓存。

## 4. 保留

- 配置 `config.json` 新增 `models`：
  - `extra`：新增选手，`{ <选手号>: { channel, model, shown, description?, efforts, fast?: { model } | { suffix }, added } }`。存下全部要用的信息，名单以后变了、甚至模型下线了，历史记录照样显示得出来。
  - `dropped`：主人不保留的选手号（内置的、新增的都可以）。
  - `seen`：`{ <通道>: [模型名…] }`，主人上次保存选择时名单里有的模型；之后新冒出来的在界面上标“新”。
- **保留的** = （内置 ∪ extra）− dropped。至少保留一位。
- 不保留的：不出现在“选手与模型”表里，派活被拦（“主人没有保留 X，请换一位”）；历史、打分、档案照常显示。再勾上就回来，原来的开关和强度设置还在。
- 新保留的模型缺省：启用，允许的强度全开，快速版按支持情况。
- 只有主人能改（桌面应用的桥）；命令行只能看和刷新名单。

## 5. 底线（不因为自动发现放宽）

- 强度只开中档、高档、超高档；Cursor 只收三家；Codex 只收公开的；DeepSeek 的特殊换算照旧。
- 隔离、自检按通道做，同一个通道里换模型不影响（实测依据见 design.md 第 7 节）。
- **模型下线**：保留着的模型，最近一次成功问到的名单里已经没有它 → 界面标“已下线”，派活时拦下（“X 的模型 Y 已经不在 Z 的名单里，请主人在设置里换一个”）。名单没问到（`error`）时不算下线。内置的 DeepSeek 两位不做这项检查。
- 主人设置（启用、强度、快速版）、额度停派线照旧，按选手号记。

## 6. 入口

- 命令行：`xagents models`（照旧核对，另列出每家发现的模型和保留情况）、`xagents models refresh`。
- 桥（白名单，参数先检查）：`modelsRefresh()`、`modelsKeep(channel, models: string[])`（这一家保留哪些模型名；整份替换；模型名必须在最近的名单里，或已经是这一家的选手）。
- 看板数据 `View.models`（`src/core/view-types.ts` 的 `ViewModels`）。
- 界面：设置 → 选手与模型，每家组头右边“管理模型”按钮，见 [ui-spec.md](ui-spec.md) 第 10 节。
