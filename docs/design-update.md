# 在线更新：装一次，以后收到新版本重启就行

状态：后台、桥、发布脚本及离线测试已实现（2026-10-10）；界面、完整平台打包和真实环境验收由负责人衔接。主人确认：这是要发给用户用的，“我们更新后，用户可以收到更新通知并更新”。第 6 节的三件事由负责人按缺省定了，真正要主人本人做的只有生成密钥和每次发版点头。

## 1. 主人要什么

> 我想增加一个更新功能，以后用户直接接收更新重启即可，而不是每次重新构建。

现在的装法（[README](../README.md)）是：拿源码 → `pnpm install` → 把命令行链到 `~/.local/bin` → `npm run install-app` 自己打包、装进“应用程序”。每出一版都要重来一遍打包和安装，装的时候应用会被关掉再打开。

要变成：**装一次**；以后有新版本，应用里提示“有新版本”，点一下，下载好后重启就是新版。

## 2. 先看清现状（2026-10-10 实测）

派活工作台其实是三样东西，现在分散在三个地方：

| 是什么 | 现在在哪 | 说明 |
|---|---|---|
| 平台本体：命令行、核心代码、隔离模板、给选手的规矩、srt | 源码目录（`bin/`、`src/`、`sandbox/`、`rules.md`、`node_modules`） | 命令行用本机的 Node 24 直接跑源码 |
| 桌面应用 | `/Applications/派活工作台.app` | 只装了界面和打包后的后台 |
| 登记处 | `~/.xagents` | 任务、群聊、设置，和版本无关 |

两条实测结论，决定了方案怎么做：

1. **装好的应用不是完整的平台。** 安装包里只有 `out/`、`package.json` 和一个小脚本，没有平台源码。所以在应用的协作页里 @ 一位选手，会报“没能发出：ENOENT, src not found in …/app.asar”（消息其实已经落盘、排上了队，但推进进程起不来，要等命令行那边下次叫醒）。这是现在就存在的毛病，只是之前的冒烟测试跑的是没打包的版本，没碰到。
2. **应用自带的运行时能直接跑平台源码。** 用装好的应用自己的程序、以“当普通 Node 用”的方式（`ELECTRON_RUN_AS_NODE=1`）跑 `bin/xagents workers`，结果正常；它带的是 Node 24.21，能直接跑 TypeScript。也就是说应用可以把整套平台带在身上，用户连 Node 都不用装。

所以“更新功能”分两步，第一步是地基：

- **第一步：让应用自带完整的平台。** 平台只剩“一个应用”这一样东西要更新。
- **第二步：应用自己收更新。** 发布一份签过名的清单和安装包，应用核对无误后换掉自己，重启生效。

## 3. 第一步：应用自带完整的平台

第一步已实现并做过真实验收（2026-10-10，结果见第 7 节）。

- 安装包带上 `Contents/Resources/platform/`，不压进 asar。由打包钩子 `scripts/after-pack.cjs`（electron-builder 的 `afterPack`）把 `out/platform` 原样拷进去，并逐个文件核对名单和大小、确认没有符号链接；不用 `extraResources`，因为实测它会悄悄丢掉其中的 `node_modules`（927 个文件只剩 79 个）。内容：`bin/`、`src/`、`sandbox/`、`rules.md`、`guide/`、`package.json` 和 srt 的生产依赖链。`scripts/prepare-platform.mjs` 在 `out/platform` 准备真实文件，递归展开 pnpm 符号链接，不带开发依赖；当前 5 个依赖包，共 927 个文件、约 18 MB（未压缩）。Python 桥也在这份平台中，已去掉 `asarUnpack`。
- 平台根目录统一在 `src/core/paths.ts` 的 `resolveToolRoot()` / `toolRoot`：asar 中的后台根据 Electron 自带的 `process.resourcesPath` 找 `platform`，缺目录明确报错；开发构建、源码 CLI 和运行快照继续取自己的根目录。根目录不接受外部环境变量覆盖，已有快照不会切回安装目录的另一版本。
- 起平台进程统一用 `src/core/node-runtime.ts` 的 `nodeRunner()` / `nodeCommand()`：普通 Node 用 `process.execPath`；Electron 用同一程序加 `ELECTRON_RUN_AS_NODE=1`。入口 `node-entry.ts` 随后清掉开关、把 `process.defaultApp` 设为真（否则 srt 用的参数解析库按 Electron 的习惯把脚本路径当成用户参数，srt 会在隔离里再套一层自己，实测启动失败）并执行目标脚本；推进进程再起看管进程、看管进程再起 srt 时都重新设置，选手拿不到这个变量。自检仅调整启动方式，探针正文不变。
- **命令行后台**：`app/main/cli-launcher.ts` 提供 `cliLauncherStatus()` 和 `installCliLauncher({ replace?: boolean })`。状态是 `installed`（当前应用的完整启动脚本）、`missing`、`other`（包括源码链接、悬空链接、其他应用位置的脚本）；开发版状态为 `other`，安装报“开发版不安装命令行”。安装在锁内写临时可执行文件再改名，路径和参数正确引用，已有其他文件必须显式选择替换。脚本只用应用自带运行时执行平台中的 `bin/xagents`，同位置更新后自然就是新版。
- **命令行的界面**：设置 → 通用 → 命令行（[界面规范](ui-spec.md) 第 18 节），通过桥上的 `cliStatus()` / `cliInstall(replace)` 调上面两个函数；开发版显示“开发版不安装命令行”。
- 开发的人照旧使用源码 `bin/xagents`、`npm run dev`、`npm run build && npx electron .` 和 `npm run install-app`。安装脚本只停窗口主进程，避免把同一可执行程序启动的平台后台进程也停掉。
- `scripts/check-desktop-bundle.mjs` 保留原有外部依赖检查，并检查平台必需文件、srt 依赖完整且没有符号链接。`npm run pack` 顺序是构建 → 准备平台 → 检查 → builder。
- 已补离线回归测试：路径选择、Node/Electron 启动与变量清理、真实依赖链复制和独立加载、命令行安装与拒绝覆盖。这些都是替身测试，打包丢文件、srt 套娃两处毛病它们都没测出来，是真实打包、真实唤醒选手时才露出来的；所以凡是动到打包和隔离启动的改动，必须打一次真包、真跑一遍。

这一步不联网，不改变选手隔离规则。

## 4. 第二步：收更新

### 4.1 用户看到的

- 顶栏右边多一个很小的提示（有新版本时才出现）：“有新版本 0.3.0”。点开是一个小弹窗：版本号、更新说明（几行大白话）、“下载并安装”“以后再说”。
- 下载、核对都在后台做，有进度。好了以后按钮变成“重启以完成更新”。**不会自己重启**，什么时候重启主人定。
- 重启只是关掉窗口再开：在跑的活、群聊不受影响（看管进程和推进进程本来就是独立的进程，各自带着自己那一轮的运行包）。
- 设置 → 通用 多一组“更新”：当前版本、“检查更新”按钮、“自动检查更新”开关。
- 出错时说人话：“没能下载更新：……”“更新包没通过核对，没有安装”。失败了什么都不换，应用照旧能用。

### 4.2 怎么保证装上的是真的

沿用我们另一个桌面应用已经在用的做法：

- 每个版本发一份**清单** `latest.json`：版本号、各平台安装包的地址、大小、SHA-256、更新说明、最低支持版本。清单用 Ed25519 **私钥签名**。
- **公钥编进应用**。应用只认签名对得上的清单，再按清单里的大小和 SHA-256 核对下载的包，两样都对才安装；任何一样不对就丢掉，不安装、不重试别的地址。
- 私钥只在主人手里（离线保管，另放一份在发布流水线的机密里），不进仓库，不交给任何选手或负责人。
- 只从打包时写死的地址取清单和安装包（HTTPS）；跳转只认打包时写明的那几个主机，别的不跟；不带任何本机信息（不带设备号、不带用量，只是普通的下载请求）。
- 不降级：清单里的版本不比现在新就不动。

### 4.3 怎么换

- 下载到应用自己的数据目录里，解开，核对解开后的应用签名（`codesign --verify --deep --strict`）。
- 重启时：把旧应用移进废纸篓（和现在的安装脚本一样留一份，好回退），把新应用放到原位置，再打开。换的过程由一个独立的小程序完成（应用退出后它还活着），失败就把旧的放回去。
- 应用装在没有写权限的位置时（比如别人装的），提示用户手动下载，不去要管理员权限。

### 4.4 怎么发布

- 版本号开始认真用（`package.json` 的 `version`，从 0.2.0 起）。
- 发布流水线（GitHub Actions，在公开仓库 heihuzi-labs/captain-agents 上）：打标签触发 → 构建 Mac 苹果芯片版 → 本地签名 → 打成 zip → 算大小和 SHA-256 → 生成并签名清单 → 自己先验一遍 → 放到发布位置。
- **每次发版都是对外动作，由主人点头**（或者主人自己打标签），负责人不自己发。
- 负责人平时在本机验收新版仍然用 `npm run install-app`，不走发布。

### 4.5 要改的规矩

[AGENTS.md](../AGENTS.md) 现在写着“桌面应用自己不开端口、不联网、不读密钥和登录文件”。在线更新必须让应用联网，这一条要改成：

> 桌面应用自己不开端口、不读密钥和登录文件；**只为检查和下载更新联网**：只连打包时写死的清单主机与跳转主机名单，只认签名对得上的清单和大小、哈希、应用签名核对无误的安装包，不带任何本机信息；主人可以在设置里关掉自动检查。窗口仍然不能联网，只能通过桥上白名单里的函数做事，参数先检查。

选手的隔离、联网总开关、其余底线都不变。

### 4.6 实际清单协议

`latest.json` 是 UTF-8 JSON，外壳只有两个字段：

```json
{
  "body": "{\"version\":\"0.3.0\",\"publishedAt\":\"2026-10-10T12:00:00.000Z\",\"notes\":\"修好更新下载\",\"minimumVersion\":\"0.2.0\",\"packages\":{\"darwin-arm64\":{\"url\":\"https://updates.example.invalid/0.3.0/arm64.zip\",\"size\":123456,\"sha256\":\"aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa\"}}}",
  "signature": "这里放 64 字节 Ed25519 签名的标准 Base64"
}
```

上面的签名和哈希是格式示意，不能用于安装。将 `body` 这个**字符串**编码为 UTF-8 后签名；应用直接验这些字节，验过后才解析内部 JSON。禁止先解析、重排字段或重新序列化再验签。外壳的 JSON 转义方式不参与签名，解码得到的正文字符串必须保持不变。公钥是 32 字节原始 Ed25519 公钥的标准 Base64（不是 PEM），签名是 64 字节标准 Base64。

正文解析后是：

```ts
{
  version: string;
  publishedAt: string;
  notes: string;
  minimumVersion: string;
  packages: Record<string, { url: string; size: number; sha256: string }>;
}
```

- 外壳最多 128 KiB；正文最多 64 KiB。外壳、正文及包对象的未知字段一律拒绝，缺字段也拒绝，防止发布脚本拼错字段或产生两个客户端理解不同的协议；扩展协议需要先发布兼容客户端。
- 版本号只能是无前导零、无后缀的 `x.y.z`，总长最多 32 字符，每段为安全整数。逐段按数值比较，相等或更旧直接返回无更新，永不降级。
- `publishedAt` 必须是可往返的 UTC ISO 时间，如 `2026-10-10T12:00:00.000Z`。
- `notes` 是 1–8000 个 UTF-16 码元的非空文字，可换行、制表，不接受其它控制字符和双向控制符。窗口必须作为文字显示，不能执行 HTML 或解释成脚本。
- `minimumVersion` 不得高于发布版本。当前版本低于它时，提示手动安装，不自动跨越不兼容版本。
- 包列表 1–16 项，键形如 `darwin-arm64`、`darwin-x64`；按运行平台和芯片选择。所有平台的包都先校验，有一个坏字段整份拒绝；缺当前平台包时说明“这个平台暂时没有更新包”。
- 包地址最多 2048 字符，只认 HTTPS，不接受用户密码、空白或 URL 片段；大小为 1–1073741824 字节的整数；SHA-256 是 64 位十六进制，大小写都接受。

纯函数见 `app/main/update-feed.ts`；发布工具复用同一份核对函数，协议没有第二套实现。

### 4.7 取数与下载文件

打包配置 `electron.vite.config.ts` 将 `XA_UPDATE_FEED`、`XA_UPDATE_PUBLIC_KEY`、`XA_UPDATE_HOSTS` 编入主进程；第三项是逗号分隔的 `host[:port]`，为空就只有清单所在主机。运行时修改环境变量不能改变已编进应用的配置。用 Node HTTPS，独立请求，不共享窗口会话，不读取系统凭据，不发送 Cookie、设备号、用量或自定义身份；固定请求头为 `User-Agent: Xagents/<当前版本>`、`Accept: */*`、`Accept-Encoding: identity`，另有协议必需的 Host 等头。

每个初始地址和每次跳转都检查 HTTPS 与精确 `host`（含非默认端口），最多跟随 5 次跳转，不转发来源地址；超出名单立即停止。每次取数全程最多 10 分钟（包含跳转和读取），失败没有换地址重试。所有请求只在主进程；`security.ts` 的生产 CSP 和窗口请求拦截不变。

下载目录是 `app.getPath('userData')/updates/`，绝不写到登记处：

- 启动及每次下载前删除该目录直接子项中的 `*.part`；包先写 `package.zip.part`（0600），边收边计数和计算 SHA-256。超过声明大小立即停；短包、哈希不符、断开、超时都会删半份文件。
- 大小和哈希都正确才改名为 `package.zip`。解压前检查 ZIP 目录、本地头、总展开大小（最多 4 GiB）和链接；禁止路径穿越、外链、链接父目录、重名、特殊文件及 ZIP64。
- 用系统 `ditto -x -k` 解到 `updates/unpacked/`，必须只有一个顶层 `.app`（允许 ZIP 的 `__MACOSX` 元数据），内部符号链接必须留在应用内；核对 `CFBundleIdentifier = app.xagents.desk`、`CFBundleShortVersionString = 清单版本`，再运行 `codesign --verify --deep --strict`。不通过删解压目录；无论成功失败都删 ZIP。

### 4.8 状态机与安装事务

状态与桥严格使用第 6.1 节的类型，不进看板数据。状态转换：

```text
off（固定，不取数）
idle/error/available → checking → idle 或 available 或 error
available → downloading（含核对与解压期间）→ ready 或 error
ready → 用户点重启 → 独立安装小程序 → 新版打开
```

操作互斥；没有可下载更新、未就绪、正在处理、多余参数或非布尔开关都拒绝并给出中文原因。操作本身失败通过状态推送 `error`，不弹系统通知；再检查会清掉旧错误。已就绪时拒绝再次检查，防止丢掉已经核对的包。自动检查跳过正在处理、已发现版本和已就绪状态。启动 1 分钟后检查，此后每 24 小时检查；关开关取消定时器，重新打开后再等 1 分钟；手动检查不受开关限制。开关通过核心专门函数加锁、原子写入 `config.json`，缺省 true，普通补丁拒绝这个字段。

缺清单地址、公钥、开发模式或未打包时，固定 `{ phase: 'off', reason: '这个版本不带在线更新' }`。其它平台 `off` 并说明暂不支持；不正常的 `.app`、路径含符号链接、App Translocation 或应用/父目录不可写时也 `off` 并提示手动安装。检查时发生网络、配置、验签、字段错误进入 `error`，应用其它功能不受影响。

解压后的检查和清理一律用 Electron 的 `original-fs`（主进程里 Node 自带的文件接口会把 `.asar` 当成一个虚拟目录，走进去就查错、删不干净；实测发现）；“链接有没有指到应用外面”按应用解析后的真实路径比（数据目录可能在一层符号链接后面，例如 `/var` → `/private/var`）。

重启前再检查安装路径、权限、暂存应用标识/版本/签名。应用在数据目录 `updates/install-随机名/restart.sh` 写出独立 Bash 小程序（0700），标准输出和错误写入同目录 `result.log`；使用绝对系统命令，生产不从环境变量替换命令。参数通过 argv 传入，脚本始终双引号引用路径；不用应用自己的 Electron 运行时，因此应用退出后仍能工作。启动小程序成功后才请求应用退出，重复重启调用会拒绝。

小程序：

1. 等待主应用 PID 退出，最多 60 秒；超时不替换。
2. 在原安装目录下创建唯一 `.xagents-update-*`，复制完整新应用并核对标识、版本和签名；复制失败旧版仍在原位。
3. 在 `~/.Trash/派活工作台-更新-*` 唯一目录复制旧应用并验签。这一步兼容废纸篓在另一块卷，备份完整后再动旧版。
4. 在安装目录同一文件系统把旧版原子改名为临时 `old.app`，把准备好的新版原子移到原位置，再次核对标识、版本、签名，然后 `open`。
5. 成功后清理安装目录里的临时副本，废纸篓保留旧版；任何命令失败或收到可捕获退出信号时，将临时旧版放回原位并打开旧版。恢复本身遇到文件系统故障时不删备份，日志写明旧版位置。断电、SIGKILL、磁盘损坏不属于可捕获失败，需要人工恢复。

不强杀主应用或工作进程，不提权。能否从真实签名 ZIP 更新、系统安全提示、任务跨重启继续运行仍须负责人在真实环境验收。脚本只确认 `open` 命令成功，无法保证新版启动后的业务行为；新版崩溃不做自动健康回滚。

发布操作、密钥责任和验收步骤见 [发布清单](release-checklist.md)。

## 5. 现在不做的

- **苹果开发者签名和公证**：现在是本地签名。应用自己下载的更新不带“来自互联网”的标记，替换后能正常打开，所以更新这条路不依赖它。但新用户**第一次**从网上下载安装时仍会被系统拦一下（要右键打开），这要等做开发者签名和公证才能解决，算在“做成产品”那一步里，不在这次范围。
- **Intel Mac 和 Windows**：清单的格式一开始就按“多平台”设计，但这次只出苹果芯片版。
- 灰度放量、强制更新：清单里留“最低支持版本”一个字段，放量先不做。

## 6. 定下来的做法（负责人定，主人随时可以改）

1. **应用联网的口子**：自动检查。启动一分钟后查一次，之后每 24 小时一次；设置里有“自动检查更新”开关（缺省开）和“检查更新”按钮。下载、安装、重启都要用户点，应用不替用户做决定。
2. **更新从哪儿发**：地址在**打包时**编进应用（`XA_UPDATE_FEED`，清单 `latest.json` 的完整地址），先按公开仓库的发布页来（主人 2026-10-11 定，具体填法和实测的跳转主机见[发布清单](release-checklist.md)）；以后换成自己的下载站只改这一个打包配置。下载时只允许连清单地址所在的主机，外加打包时写明的少数几个跳转主机（发布页的文件实际放在另一个主机上）；别的一概不连。没编进地址或公钥的包（开发版、本机 `npm run install-app` 装的）不带在线更新，设置里写明“这个版本不带在线更新”。
3. **签名密钥**：派活工作台专用的一对 Ed25519。公钥在打包时编进应用（`XA_UPDATE_PUBLIC_KEY`）；私钥只有主人生成和保管，发版时用。仓库里只有“生成密钥”“给清单签名”的脚本，没有任何密钥；测试用临时生成的测试密钥。

## 6.1 应用内部怎么对接（两边照这个写）

更新的状态只在应用后台里，不进登记处、不进看板数据。窗口通过桥上新增的几个函数拿：

```ts
// app/shared/ipc.ts
export type UpdateState =
  | { phase: 'off'; reason: string }                                   // 这个版本不带在线更新
  | { phase: 'idle'; checked: string | null }                          // 没有新版本；checked 是上次查到结果的时间
  | { phase: 'checking' }
  | { phase: 'available'; version: string; notes: string; size: number }   // notes：更新说明，纯文字
  | { phase: 'downloading'; version: string; received: number; size: number }
  | { phase: 'ready'; version: string }                                // 已下载并核对无误，重启生效
  | { phase: 'error'; message: string };                               // 给人看的中文原因；下次检查会清掉
export type AppInfo = { version: string; update: UpdateState; autoCheck: boolean };

// XaBridge 新增（都不收多余参数，后台先检查参数）
appInfo(): Promise<AppInfo>;
onUpdate(callback: (state: UpdateState) => void): () => void;   // 状态一变就推
updateCheck(): Promise<UpdateState>;       // 主人点“检查更新”
updateDownload(): Promise<void>;           // 只在 available 时可用；进度和结果走 onUpdate
updateRestart(): Promise<void>;            // 只在 ready 时可用：换上新版并重新打开
setAutoUpdateCheck(on: boolean): Promise<AppInfo>;
```

- “自动检查更新”存在 `~/.xagents/config.json` 的 `autoUpdateCheck`（缺省 true），不走普通设置补丁，和联网总开关一样用专门的函数。
- 命令行的安装（第 3 节）由第一步提供两个后台函数（查状态、安装），桥和界面由负责人接。

## 7. 怎么验收

- 第一步：打包后的应用里，在协作页 @ 选手能叫醒；删掉本机的源码目录链接后 `xagents` 仍能用（走应用里的那份）；`npm run verify` 全过；打包前检查通过。
- 第二步：用测试密钥和本机起的假下载站走一遍——清单签名不对不装、包被改过一个字节不装、版本不比现在新不动、下载到一半断了不坏、装到一半失败能回到旧版；真的发一个测试版本，从旧版点“下载并安装”→ 重启后是新版，在跑的活没受影响。

### 7.1 验收结果（2026-10-10，负责人在隔离外真实跑的）
