# 选手按这台电脑的实际情况来；Codex 接什么接口都能派

**状态：** 主人 2026-10-12 点头后已实现：三条规则、手动添加模型名、界面，都在分支上，macOS 上整套验收通过，Windows 流水线上核心测试和界面测试通过。探针见 [research/codex-endpoint-2026-10-12.md](research/codex-endpoint-2026-10-12.md)（macOS 和三台 Windows 机器结论一致）。还差：在主人接着自定义接口的那台电脑上真派一件活。
**写于：** 2026-10-12。三条规则是主人当天在对话里定的。
相关：[design-models.md](design-models.md)、[design.md](design.md) 第 7 节、[design-windows.md](design-windows.md)。

## 1. 起因

一台新装的电脑打开应用后：

- 选手名单是写死的八位，全部“开启”，不管这台电脑装没装、这种系统上能不能派。
- 顶栏和“表现”页固定画 Codex、Grok、Cursor 三家的额度。
- Codex 接的不是官方接口时：平台显示的额度是对方转回来的别人的数字；而且平台启动 Codex 时不读用户的配置（`--ignore-user-config`），接口地址被一起丢掉，活派不出去（已实测：请求一次都没到自定义接口，去连了官方接口被拒）。

## 2. 原则

平台不关心你接的是谁，只要知道三件事：程序在哪、活能不能派出去、额度数字能不能信。用户不用为此多填任何东西。

## 3. 三条规则

### 规则一：找得到程序、这种系统上关得住的，才列出来

- “找得到程序”：用派活时找这家程序的同一个办法，看它在不在。DeepSeek 借 Codex 的程序，跟着 Codex 走。
- “关得住”：`src/core/selfcheck.ts` 的 `platformIsolations`，全仓库只有这一处写，界面读它。
- 每次读看板数据时现看，不存缓存，不加按钮。
- 没列出来的，在“选手与模型”页底部用一句淡色小字说明，比如“这台电脑上没找到 Grok；Cursor 在 Windows 版上暂时不能派”。
- 设置页、顶栏的额度圆环、“表现”页的额度卡片、`xagents workers`、指挥手册末尾，都只列这些。
- 主人的设置不变，仍按选手号存；“至少要留一位选手”只在列出来的里面数。没列出来的选手原来的开关留着，哪天能列了自动回来。
- 登录没登录、隔离装没装，不归这条规则管：派活时和自检本来就会报。
- 派活时的把关一条不少。这条规则只管显示，不管放行。

### 规则二：派 Codex 活时，把用户配置里“连哪个接口”那一小段原样带上

- `--ignore-user-config` 不动。平台另外从用户的 Codex 配置里只取“连哪个接口”这一段，用启动参数带进去。别的配置照旧不读、不生效，插件、连接、钩子仍然进不来。
- 钥匙仍由 Codex 程序自己去取，平台不碰。这一段里如果直接写着钥匙，平台不带这一项，派活时提示主人换个放法；钥匙不进启动参数。
- **钥匙放在环境变量里的**（主人 2026-10-12 定）：配置里点名的那一个变量，过滤之后原样交给 Codex 主程序，其余带密钥字样的照旧滤掉。任务记录里只记这个变量的名字，不记值。选手跑的命令看不到它（已实测；启动参数里另外点名把它排除，名字里不带 KEY 这类字样也一样）。
- 带的是这几项：接口的名字、地址、协议、钥匙从哪取、地址参数、重试和超时的几个数。值由平台重新写一遍再带进参数，配置里的引号、花括号混不进别的设置。
- 配置文件是手写的小解析，只认常见的一行一项的写法；认不出来的项不带，并在派活时说明（不拦派活）。用“配置档”（profile）切换接口的写法不认。
- 隔离、权限表、关掉的那些功能一个字不改：换的只是 Codex 主程序去连谁，而主程序本来就在隔离外面。
- 没写这一段的（官方登录），和现在完全一样。
- 应用里没有新设置，也没有“接法”这个概念。

### 规则三：连的不是官方接口，就不显示 Codex 的额度

- 不画圆环，不写百分比，不参与停派线，缓存里的旧数字不再拿出来用。
- 不显示别的东西代替。

### 模型

Codex 程序自带的名单照旧；“管理模型”里 Codex 这一家可以手动添加一个模型名（填名字、选允许的强度）。手动加的不做“已下线”检查。平台自己不去连接口要名单。

## 4. 底线对照

| 底线 | 怎么守 |
|---|---|
| 启动参数每一条都来自实测 | 规则二动了启动参数，先出探针报告再写代码（第 5 节） |
| 桌面应用和平台不读密钥和登录文件 | 只读配置文件里的一段；钥匙不读、不带 |
| 哪种系统开放哪几种隔离只写一处 | 规则一读 `platformIsolations`，不另写 |
| 选手名单只有 `roster.ts` 一张表 | 不变，规则一只是在它上面筛 |
| 主人的设置只能收窄不能放宽 | 没有新设置；规则一只会让列出来的变少 |

## 5. 实测结果

探针和结果见 [research/codex-endpoint-2026-10-12.md](research/codex-endpoint-2026-10-12.md)。要点：

- 现在的启动参数下，接自定义接口的人派不出活。
- 带上“连哪个接口”那一段以后活能派；被 `--ignore-user-config` 挡掉的东西（会在隔离外执行的通知程序、外部连接）仍然不执行；隔离里的命令照旧只能写副本和任务临时目录，连不了外网。
- 要带整张提供方表；只带 `openai_base_url` 一个键也能通，但每次先白试 7 次长连接。
- 钥匙放在环境变量里：把那一个变量交给主程序就能派，命令里看不到它。
- Codex 带着自定义接口时不会去问接口要模型名单，列的还是自带的。

## 6. 分工

- 探针：负责人。
- 规则二（启动参数）是安全代码：负责人写或派 Codex，另一家独立审，不交给 Haiku。
- 规则一、规则三、手动加模型名的核心部分：适合派给选手。
- 界面（设置页、顶栏、表现页）：负责人，先改 [ui-spec.md](ui-spec.md) 再改代码。

## 7. 不做

- 让用户在应用里填接口地址、再登录一遍。
- 扫描结果的缓存、状态表、“重新扫描”按钮、手动指定程序位置。
- 把别的命令行程序加成选手。
- 平台自己去连接口要名单、查余额或用量。
- Grok、Cursor 的自定义接口。
