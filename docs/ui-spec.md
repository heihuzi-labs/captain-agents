# 派活工作台界面规范

给以后所有改界面的人和 AI 看。**同一样东西只有一份实现**：图标、弹窗、按钮、标签、卡片、颜色，都从这里规定的地方取，不在别处再写一份。改样子先改这里，再改代码。

`test/ui-spec.test.ts` 会检查本规范能检查的部分（见第 8 节）。

## 1. 文件分工

| 位置 | 放什么 |
|---|---|
| `app/renderer/styles/tokens.css` | 所有变量的**唯一**定义处（深浅色两套） |
| `app/renderer/styles/ui.css` | 统一部件的样式 |
| `app/renderer/styles/layout.css` | 顶栏、看板、历史、各家表现的排版 |
| `app/renderer/ui/` | 统一部件（第 3 节）。只有这里可以画图标、弹窗外框、按钮 |
| `app/renderer/components/` | 页面和内容，只能拼装统一部件 |

## 2. 变量

颜色、字号、间距、圆角、阴影，一律写 `var(--…)`。除 `tokens.css` 外，样式文件和组件里不许出现 `#123456`、`rgb(…)` 这类写死的颜色，也不许写死字号、圆角和间距的像素数。深色模式只在 `tokens.css` 里用同名变量重新赋值，别处不写深色分支。

主人要看的信息统一用 `--text`，浅色、深色主题下与实际底色的对比度都至少 4.5:1。状态与结果标签用 `--text` 写字，底色仍用 `--sunk`、`--ok-soft`、`--bad-soft`、`--warn-soft`、`--accent-soft` 表达语义。

### 状态色（第 4 节的表只能从这里取）

`--state-queued`、`--state-running`、`--state-quiet`、`--state-decide`、`--state-failed`、`--state-lost`、`--state-done`。只用在状态圆点、看板列的主色和在跑卡片的进度条上；**卡片不画状态色边**。

`--state-decide`（“验收中”列）是一个沉稳的**石板蓝灰**（浅色 #64748b，深色 #94a3b8），不再是琥珀色：验收是负责人在处理，不催主人，所以用安静的冷灰。它和进行中的蓝（`--state-running`）、已完成的绿（`--state-done`）、批次色带那六种（紫、青绿、粉、靛、橄榄、深紫，都是饱和的颜色）都分得开：石板色饱和度很低，看起来是灰里带一点冷。

### 批次色板

`--batch-1`、`--batch-2`、`--batch-3`、`--batch-4`、`--batch-5`、`--batch-6`（#7c5cff、#0f9d9a、#d9468f、#4f5bd5、#6f8f1f、#8a5a9e）。

### 选手字母圆标（图标缺失时的兜底）

`--brand-codex`（#4b5cf0）、`--brand-grok`、`--brand-cursor`（#111111）、`--brand-claude`（#d97757）、`--brand-other`（#888888）。

## 3. 统一部件（`app/renderer/ui/`）

| 部件 | 用途，规矩 |
|---|---|
| `WorkerIdentity` | **选手身份**：只有一行写法。依次是图标、加粗正文色**模型名**、推理强度小标签、可选的“快速”小标签、可选用时；结果、状态标签 `end` 在同一行最右边。**厂家名不写成文字**：图标已经代表厂家（Codex、Grok、Cursor 各有自己的图标，Cursor 右下角再带一个模型家族角标），再写一遍名字只是重复，还把卡片撑成两行。厂家名保留在两处：整个身份的悬停提示写全（如“Cursor · Sonnet · Claude Sonnet 5.5 · 高档 · 快速 · 7 分钟”，文字拼法在 `workerMeta`，别处不许自己拼），以及图标的可访问名（`role="img"`，`aria-label` 是厂家名，屏幕朗读读作“Cursor · Sonnet Claude Sonnet 5.5 高档……”）。图标只按 `size` 取一档（`sm`、`md`、`lg` 对应 `--icon-sm`、`--icon-md`、`--icon-lg`），不为文字高度另撑大。卡片、弹窗正文、批次每一行、历史、各家表现第一列都只用它；只有一种模型的厂家，第一列就是“图标 + 模型名”。`detail`：`model` 只带模型、`setting` 加强度与快速标签、`full` 再带已结束任务的用时；默认 `setting`。`elapsed` 可传正在更新的用时。`iconOnly` 只画图标（历史一行里的小图标），提示和可访问名写“厂家名 · 模型名”。只有模型名可截断，标签和用时不截断、不换行 |
| `WorkerRow` | **选手行**：身份在左，结果、验收和状态标签 `end` 在同一行最右。行本身任何窗口宽度都不换行；窄卡片里模型、标签、用时加结果放不下一行时，只有 `end` 整块换到下一行的右边（在身份内部的 `.ident-body` 里换），保证模型名读得全，这样还放不下才截断模型名。换行时中号图标贴着第一行（和模型名同一行），不在两行中间居中。兼容现有调用：`end` 直接传入的 `Elapsed` 自动放进身份的用时位置，避免页面另写布局。看板卡片、弹窗正文、一批的每一行都用它 |
| `WorkerIcon` | 全应用**唯一**画选手图标的地方（额度条也用它）。图片加载中只占位，成功显示图片，失败退回字母圆标。别处不许写 `<img>`。带角标的图标（Cursor），角标为主图标的 45%，向右下外移 12%，带一圈和底色相同的细边，主图标不被挡太多，在 16px 的小图标上角标也认得出；字母圆标（图标缺失时）把主字母放在左上方 70% 的区域，确保“Cu”完整可见。Codex 的图标素材四周留白多，放大 1.45 倍并去掉描边后与其他家视觉一样大，各尺寸都适用。传 `label` 时图标是一张有名字的图（`role="img"`），不传就只是装饰 |
| `Modal` | **弹窗外框**：暗幕、标题栏、右上角关闭按钮、Esc 或点暗处关闭、焦点管理、两层弹窗时只有最上面一层可操作。`size`：`md` 默认、`sm` 窄（二次确认）、`lg` 大（宽约 760、高约 560，窗口小时跟着缩，设置窗口用）；`flush` 让正文不留边距、不整体滚动，由里面的内容自己分栏、自己滚动。属于多家一批的内容传 `hue`，弹窗顶部加批次色带（和卡片一样）。别处不许自己做弹窗外框或关闭按钮 |
| `TaskHead` | **任务弹窗的头部**（单家、一批都用它，别处不许自己拼）：状态圆点 + 类型标签 + 题目，题目放不下截断，悬停看全文；从一批点进某一家时，最前面多一个“← 这一批（N 家）”。一批的圆点：有一家在跑算在跑，否则有一家在排队算排队，否则有一家做完算完成，否则按出错、失联、已停。正文第一行：单家是 `WorkerRow`（身份 + 状态、验收，用时在身份里），一批是“要做什么”。设置、二次确认没有状态，标题栏只写一句标题 |
| `ConfirmDialog` | 二次确认，基于 `Modal`。写清后果；默认焦点在“先不改”；确认按钮默认用 `Button` 的危险款，不会丢东西的确认（如接入 AI）传 `tone="primary"` 用主要款；需要列出细节时传 `detail`（放在那句话下面，纯文字） |
| `Button` | 唯一的动作按钮，三种：`primary` 主要（推荐的一步，如“用这份”“发送”）、`secondary` 次要（取消、恢复默认、上一张/下一张）、`danger` 危险（会丢东西或不可撤回，如“不要了”“停下”）。`size="sm"` 用在成排的小按钮 |
| `StatTile` | **大数小卡**（表现页）：标签（`--muted` 小字）、数（`--fs-xl` 加粗、比例数字，单位用 `small`）、可选 `trend`（大数右边同一行的 `Sparkline`，卡片不因它变高）、口径（`--faint` 小字）。`--panel` 底、`--line` 边、`--r-md` 圆角、卡片阴影 |
| `Sparkline` | **小趋势线**：规则见第 15 节“图表规矩”。`values`、`labels`（每天的日期）、`format`、`unit`、`label`（整条的可访问名） |
| `MoreMenu` | **弹出菜单**（照 macOS 菜单）：`.more-btn` 是和顶栏设置按钮同一种的小图标按钮（26×26，三个居中的点，不另做图标文件）；调用方传 `label` 作 `aria-label`，带 `aria-haspopup="menu"`、`aria-expanded`。平时 `--faint`，所在行（加 `.more-row`）悬停时 `--muted`，按钮自己悬停、键盘聚焦或菜单打开时有 `--sunk` 圆角底、`--text` 色。`items` 每项传 `label`、可选 `note` 和 `onSelect`，都是纯文字；**菜单项写短词、一项一行**，能不写说明就不写（说明留给执行后的提示条）。`ref.openAt({ x, y })` 接收窗口坐标供右键复用同一菜单。菜单 `role="menu"`，每项 `role="menuitem"`；`--panel` 底、`--line-strong` 边、`--r-md` 圆角、`--shadow-menu` 阴影，最窄 140px，项 `--fs-md`、行高约 26px。**用鼠标打开时不高亮任何一项**，鼠标移到哪项亮哪项；键盘打开时第一项亮（靠 `:focus-visible`）；亮的样子是 `--accent` 底、`--on-accent` 字。普通打开在按钮下方右对齐，右键在鼠标位置；与窗口边缘留 8px，超出时往里收，过高时内部滚动；滚动和缩放后重算位置。按钮回车、空格、下箭头打开并聚焦第一项，上下循环、Home/End 跳头尾，回车/空格执行；Esc 关闭并还焦点给按钮，Tab 关闭后继续正常移动焦点。点菜单外、执行后、窗口失焦都关闭，全窗口同时只开一个 |
| `Toast` | **底部提示条**：窗口底部居中，`--panel` 底、`--line` 边、`--r-md` 圆角和 `--shadow-modal` 阴影，文字可折行；一句纯文字 + 可选一个 `Button` 小动作 + “×”（可访问名“关闭提示”）。`role="status"`、`aria-live="polite"`。`App` 用单个状态和 `showToast(text, action?)` 统一管理，每条有独立 `id`，新的替换旧的并重新计时。8 秒消失；悬停或内部按钮聚焦时暂停，两者都离开后重新计 8 秒；关闭按钮立即关闭。归档撤销成功直接关闭，不另发恢复提示；失败保留动作并沿用保存失败提示 |
| `Chip` / `CheckChip` | 状态标签，颜色表达语义：`neutral`、`ok`、`bad`、`warn`、`acc`。验收结果用 `CheckChip`。**项目小标签**也是它（中性色，`title` 写“项目：名字”），出现规则见第 14、16 节 |
| `Card`、`MemberRow`、`BatchGroup` | 看板卡片。**没有状态色边**：状态靠卡片在哪一列、卡上的状态标签表达（第 4 节）。多家一批加顶部**批次色带**（`hue`）；`marked` 在右上角加“有留言等负责人回复”的小圆点（不写字）。一批同时在跑的活用 `BatchGroup` + `MemberRow` |
| 折叠箭头 `.disclosure` | 可折叠的标题栏最左边、名字前面的小箭头（和访达侧栏一样），纯样式画（两条边框转 45°），不另做图标：所在按钮 `aria-expanded="true"` 时朝下，`"false"` 时朝右，颜色 `--muted`，减少动效时不做转动动画。现在用在已完成列的项目卡，以及历史页“已归档”一节的标题（第 16 节） |
| `ReplyDot` | 卡片角上的留言小圆点（`Card` 的 `marked` 已包含） |
| `Dot`、`Elapsed` | 状态圆点（传 `state`）、用时（在跑的每秒只更新这一小块文字） |
| `TimingNote` | **每一步的时间**：弹窗“进展”标题下方的一行小字（`.timing-note`，字号 `--fs-sm`，颜色 `--faint`，过长折行，纯文字）。文字只用核心的 `describeTiming`（拼法不在界面另写），例如“大部分时间在想，跑命令不到 1 分钟，共 45 步”。任务的 `timing` 为 `null`（老任务、还没有记录）时整行不出现，不写“没有记录”之类的占位。在跑的活跟着 `Elapsed` 同一个计时器刷新（每秒只改这一小块文字），结束的活固定不变 |
| `Switch` | **滑动开关**：全应用所有“开 / 关”只许用它（防休眠、通知、开机启动、选手启用……），不许再出现浏览器自带的方形勾选框（`type="checkbox"`，见第 8 节）。`role="switch"` 的按钮，`label` 是可访问名，空格或回车切换，焦点框跟全应用一致。`disabled` 整个变灰点不动；`locked` 传一句原因：现在不能改，仍可聚焦，悬停写这句原因，点了没反应（`aria-disabled`）。关着用 `--switch-off` 轨道，开着用 `--accent`，滑块 `--knob` |
| `CheckDot` | **勾选点**：表格里的“选 / 不选”，小圆点，`role="checkbox"`，勾了的填 `--accent` 并画对号（不只靠颜色）。参数和键盘同 `Switch`（`label`、`checked`、`onChange`、`disabled`、`locked`）。放在表格的一格里，居中对齐 |
| `Segmented` | **分段切换**：一小排互斥的选项，当前项是浮起的块（`--seg-thumb`，带 `--shadow-card`），其余是次要文字色（`--muted`），整排坐在 `--seg-track` 底槽里，像 macOS 工具栏的分段控件。`role="tablist"` / `role="tab"`，`aria-selected` 表示当前项；只有当前项在 Tab 序列里（`tabIndex` 0，其余 -1），左右键切换并把焦点跟过去（首尾循环，Home / End 跳头尾）。焦点框只在键盘操作时出现（第 6 节）。`title` 是悬停提示（如“看板（⌘1）”）。所有段字号、字重一样，切换时不抖。`disabled`：整排变灰、点不动也聚焦不到（`aria-disabled`，各段是 `disabled` 按钮），当前项保留（设置里“存储”的天数在自动清理关着时用）。顶栏页面切换用它，不带件数角标。别处需要“几选一”也可以用它 |
| `Select` | **弹出菜单**：macOS 系统设置那种小下拉按钮——当前值 + 右边小箭头（`--muted` 细线），`--panel` 底、`--line-strong` 边、`--r-md` 圆角、`--shadow-card`，高 24px，数字等宽；点开是系统原生菜单（原生 `select`，键盘、读屏都走系统）。挑一个数或选项多于三四个时用它，比 `Segmented` 安静（设置里的派活限制用）。放进 `SettingRow` 时整行是 label，点标题也能打开。`disabled` 变淡、点不动 |
| `QuotaRing` | **额度圆环**：SVG 画的细环，直径 `--ring`，从 12 点钟方向顺时针填到已用的百分比。颜色沿用 `quotaLevel`：小于 80% 用灰色 `--muted`（平时安静），80% 起 `--warn`，95% 起 `--bad`（2026-09-29 平时灰色、快用完再变色）；底环是 `--line-strong`。查不到（`used` 为 `null`）时是一圈灰色（`--faint`）虚线空环。`children` 放在环中心（顶栏放该厂家的 `WorkerIcon` 小号）。`role="img"`，`label` 是可访问名（如“Codex：周额度 63%”）；百分比数字不画在环上，由 `StatusCluster` 写在环旁边 |
| `StatusCluster` | **顶栏右边的状态块**：三家各一个 `QuotaRing`（中心是厂家图标，环表示这家用得最多的那个池的百分比），环旁边写百分比数字（`.quota-pct`，平时 `--muted`，80% 起和环一起变 `--warn`、95% 起 `--bad` 并加粗；查不到写“—”），后面一个隔离自检小圆点（正常 `--state-done`、没过 `--state-failed`、还没自检或已过期 `--state-queued`；`role="img"`，可访问名“隔离正常”“隔离自检没过”“还没自检”，悬停写自检原文说明）。整块是一个按钮，点一下去“各家表现”页；悬停提示按家写：厂家名（套餐）、各池百分比、数据时间（这次没查到时写明），最后一段是隔离自检原文。悬停只有整块一份提示，圆点上的除外（单独写原文说明）。任何窗口宽度都完整显示，不换行、不缩掉 |
| `SideNavLayout` | **两栏布局**：左边窄栏（竖排页签，`role="tablist"`），右边内容区单独滚动（`role="tabpanel"`）。上下键切换并把焦点跟过去（首尾循环，Home / End 跳头尾），只有选中的页签在 Tab 序列里，选中页签带 `data-autofocus`。全应用只有这一种两栏：设置窗口（放进 `flush` 的 `Modal`）和历史页（放进页面，第 16 节）都用它；页面里用时传 `className` 定左栏宽度和整体高度（`history-layout`，样式在 `layout.css`）。每个页签除名字外可带 `badge`（右边的小数字）和 `note`（名字下一行小字，`--muted`），设置页不用；内容自己只画选中的那一项。左栏页签下面可以再放一节（参数 `footer`），历史页的“已归档”放在这里，不另做两栏 |
| `SettingGroup`、`SettingRow` | **分组面板和设置行**：`SettingGroup` 是圆角浅底面板（组内行之间细分隔线），可选 `head` 是组头（浅灰底一行）；`SettingRow` 一行 = 左边标题（`note` 是下面一行小字说明；可选 `icon` 放在标题前，接入 AI 放各家图标；`dim` 整行变淡）+ 右边控件，整行是一个 `label`，点标题就是操作里面的控件；右边是一组按钮（如外观的 `Segmented`）时传 `group`，整行改成带名字的 `role="group"`，点标题不会误点到第一个按钮。设置的每一页都用它们，不再另写行样式 |
| `ColorField` | 取色框，外观和输入框（`.field`）一样，深浅色都跟主题。拖动时只改显示；松手（`change`）才把最后的颜色交给 `onCommit` |
| `CloseButton`、`hasNestedModal` | 弹窗右上角的关闭按钮（只在 `Modal` 里用）；是否叠着两层弹窗（键盘处理用） |
| `cssVars` | 把 `var(--…)` 交给元素自己的变量（批次色带、列主色），值不写颜色 |
| `Panel`、`Section`、`EmptyState` | 面板、带小标题的内容块（标题可以是一句话，也可以是“文字加一个 `Chip`”，如弹窗里的“真实验收：通过”）、空状态（一句话，浅色居中） |

导航类的专用样式（筛选胶囊、“全部历史 →”、“← 这一批”、顶栏最右的“设置”按钮 `.top-icon`）不是 `Button`，样式在 `layout.css`。设置必须有一个在窗口里一眼可见的入口（2026-09-29：主人只靠 ⌘, 和菜单栏找不到设置）；图标是原创线条“三根滑杆”（齿轮在小尺寸下像太阳，会被当成深浅色切换），颜色跟随文字。

## 4. 状态颜色表

卡片（看板、历史、弹窗里的行）**一律不画左边的状态色条**。状态只靠两样表达：卡片在哪一列；卡上的状态标签（`Chip`：负责人在挑、中途断了、出错了、验收没过）。已完成列的结果只标例外（没用、等负责人处理、已停），采用了不挂标签。

| 状态 | 变量 | 用在 |
|---|---|---|
| 排队 | `--state-queued` | 状态圆点（排队的活放在进行中列最上面，卡上带灰色“排队”标签，不再单独成列） |
| 在跑 | `--state-running` | 进行中列、状态圆点（脉动）、进度条 |
| 较久没动作（10 分钟） | `--state-quiet` | 在跑超过 10 分钟没有新动作：那张卡的进度条变琥珀色，**不写任何字**；悬停提示写事实“最近 12 分钟没有新动作”。超出平时用时，进度条也是这个颜色，并写“比平时久 N 分钟” |
| 验收中 | `--state-decide` | 验收中列（石板蓝灰；卡上是“负责人在挑”标签，灰底中性标签，不用琥珀） |
| 出错 | `--state-failed` | 状态圆点（卡上是“出错了”“验收没过”标签） |
| 失联 | `--state-lost` | 状态圆点（卡上是“中途断了”标签） |
| 完成 | `--state-done` | 已完成列、状态圆点 |

批次色带只用 `--batch-1` 到 `--batch-6`，按派出顺序轮换；只有真正有两家以上的批次才有色带。色带是区分批次的，不表达状态，卡片和弹窗顶部都有。

## 5. 文案规则

- 全部中文、大白话，只写人需要知道的；**不写猜测**（如“可能卡住”），状态用颜色表达。
- **给主人看的字描述状态、不下命令、不催促。**
- **不写工程说法**：进程、日志、副本、分支、提交、看管这类词不出现在给主人看的字里，换成人话。例：失联的卡写“做到一半停了”，不写“看管进程已经不在”。
- 一批做完后的验收小结：没有一家通过验收，只写“2 家做完了”；有通过的，写“2 家做完了，1 家通过验收”；全部通过，写“2 家都做完了，都通过验收”。
- 不出现已经不存在的功能：没有“报告”“改动”“验收详情”“跟我说：……”（唯一例外：设置“存储”的说明“任务记录、报告、改动和打分都留着”，那是讲清理后留下什么）。验收中的卡片下方写“负责人会处理，你也可以点开插手”。详情和批次弹窗里，还没拍板、并且下面有按钮时，按钮上方写“负责人会处理；你想直接定，也可以点下面的按钮。”按钮本身保留，主人可以选着插手。
- 推理强度：`medium` 写“中档”，`high` 写“高档”，`xhigh` 写“超高档”，其他值照原样；各用一个小标签，快速版再跟一个独立的“快速”小标签（没有强度时也显示）。
- 选手身份：图标、模型名（加粗）、强度标签、快速标签、用时按顺序排在一行，全部用正文色，不写厂家名（图标已代表厂家；纯文字的场合，如菜单栏下拉、系统通知、命令行输出，照旧写厂家名）。模型用展示名（Cursor 的三位写实际模型，如“Grok 4.7”“Claude Opus 5.5”“Claude Sonnet 5.5”）。
- 时长：不满 1 分钟写“N 秒”，不满 1 小时写“N 分钟”（卡片上用短写法；弹窗状态行可写“15 分 00 秒”），再长写“N 小时 M 分”。
- 数字：件数、家数用阿拉伯数字加量词（“3 家”“2 件”）；百分比写“80%”。验收中有几件，只写在这一列的列头，不写进顶栏。
- 按钮用动词：用这份、不要了、停下、重做、发送、先不改、确认停下、确认不要、恢复默认。
- 错误只写一句原因：“没能办成：……”“没能发出：……”。

### 进展

弹窗“进展”只用统一部件 `ActivityList`：最多最近 12 条，新的在上面，每行三列（时间、大类、具体动作）。大类来自 `human()`；连续同类只在第一条写，后面的格子留空，遇到说话或其他大类重新计数。具体动作是 `activity.text` 原文，用 `--font-mono` 等宽字体、`--text` 正文色，保留空白、过长折行、不截断。时间用 `--muted`，大类用 `--text`。选手说话（`kind === 'say'`）整句原样显示，占大类和具体动作两列，使用正文字体。

电脑休眠（任务记录的 `sleeps`）放进时间线它该在的位置，做成一条居中的虚线分隔行（`.activity-sleep`，`--muted`）：“23:15–23:25 电脑休眠，选手暂停；醒来后已接着干”，醒来后没有新动作时写“醒来后还没有新动作”。不许把休眠单独排在列表最下面：列表是新的在上面，放在最下面会被读成“停在这里了”（就这样误会过）。

**每一步的时间**：“进展”标题的正下面、动作列表的上面，放一行 `TimingNote`（第 3 节），拼法见第 9 节。在跑的活（在跑、排队、失联）和动作列表一起出现；已结束的活原来不显示“进展”，现在只在它有 `timing` 时显示“进展”一节，里面只有这一行、没有动作列表；没有 `timing` 的已结束的活照旧没有“进展”这一节。

这里的具体动作是选手的原始动作，不算“工程说法”，不受上面“不写工程说法”的限制；只在弹窗“进展”里显示。卡片上仍只写大类。

## 6. 焦点与键盘

- **焦点只落在能操作的控件上**：按钮、输入框、开关、链接。容器（弹窗外框、面板）不接收焦点，也不显示焦点框。
- **焦点框只在键盘操作时出现**，全应用一个规则：可操作控件在 `:focus-visible` 时显示 2px 的 `--focus` 焦点框；鼠标点击不显示。脚本挪过去的焦点（弹窗打开时自动落焦）也照这个规则：最近一次操作是鼠标、或者还没操作过时不显示框，最近一次是键盘（不带 ⌘、Ctrl、Option 的按键，如 Tab、方向键、回车、Esc）时显示。这个判断在 `ui/focus.ts`，只在根元素上记一个 `data-input`，别处不许另写。例：用鼠标（菜单、托盘）打开设置，焦点落在左栏当前分页上，但不出现焦点框。
- 输入框、留言框获得焦点时边框换成 `--focus`，鼠标点进去也看得出正在输入的位置。
- 弹窗打开时，焦点落到弹窗里第一个可操作的控件（标题栏的返回、关闭也算），需要更合适的起点时用 `data-autofocus` 指定（二次确认落在“先不改”，设置落在左栏当前分页）。关闭后焦点回到打开前的位置。
- 弹窗里 Tab 在弹窗内循环；Esc 关闭最上面一层；两层弹窗时下面一层暂时不可操作。
- 详情里 ← → 切换上一张、下一张；在输入框里输入时不响应。留言框 ⌘ 回车发送。
- 顶栏分段切换（`Segmented`）：←→ 切换页面并把焦点跟过去（首尾循环，Home / End 跳头尾）。
- 全局：⌘1、⌘2、⌘3 切页，⌘R 刷新，⌘, 设置。

## 8. 守规范的测试（`test/ui-spec.test.ts`）

1. `components/`、`App.tsx`、`lib/` 里不许直接写 `<img`、`<dialog`、`role="dialog"`、`role="alertdialog"`、`aria-modal`，不许自己写弹窗外框、暗幕、关闭按钮的样式类，不许直接用 `window.confirm` 和 `window.alert`。
2. 这些源码里不许出现写死的颜色（`#rgb`、`#rrggbb`、`rgb()`、`rgba()`、`hsl()`），不许直接写按钮的 `btn` 样式类。
3. 样式文件除 `tokens.css` 外，不许写死颜色，不许给 `font-size`、`border-radius`、`padding`、`margin`、`gap` 写像素数，`var(--…)` 用到的变量必须在 `tokens.css` 里定义。
4. `tokens.css` 深色只能覆盖浅色里已有的变量；设置里的“恢复默认”列颜色必须与 `tokens.css` 里对应的状态色一致。
5. `tokens.css` 里的每个变量、`ui/index.ts` 导出的每个部件，都必须在本文件里出现。
6. 卡片左边的状态色条不许回来：`app/renderer` 的源码和样式里不许出现状态色边的样式类（`st-` 加状态名）、`stateClass`、`CardState`、局部变量 `--state` 和 `--edge`；`Card`、`MemberRow` 不许再传 `state`；样式里不许有横向偏移不为 0 的内阴影（左右色条），也不许用状态色、语义色、批次色画 `border-left`。
7. 开关只许用 `Switch`：`app/renderer` 的源码里不许出现 `type="checkbox"`（浏览器自带的方形勾选框）。

## 9. 数据怎么算

“各家表现”、看板卡片、历史里的数字只有一份算法，写在核心（`src/core/stats.ts`、`src/core/duration.ts`、`src/core/profiles.ts`），界面和 `xagents stats`、`xagents profiles` 读同一份结果，页面里不许再自己算一遍。

- **合格**：只认派活工作台里的验收记录（`xagents verify` 留下的）。只统计有验收记录的活：一件都没有写“—”，悬停写“还没有验收记录”；有记录时写“通过数/有记录的件数 合格”，如“2/3 合格”。没有记录的活不进分母，也不算不合格；不补造过去的记录。历史里一批的“合格 x/y”同理，y 是有记录的家数。
- **平均用时**：只算做完了（`done`）的活；停下、中途断了、出错的不算。电脑休眠的时段（任务记录里的 `sleeps`）先从用时里扣掉，重叠的时段只扣一次。单件活显示的用时（卡片、历史、弹窗、`xagents status`）同样已扣掉休眠，弹窗里另有一句写明休眠了多久。
- **每一步的时间**（`ViewJob.timing`：`steps` 步数、`toolSeconds` 跑命令的秒数）：想和写的时间 = 扣掉休眠的总用时 − 跑命令。给人看的那句话只用 `describeTiming(timeSplit(...))`（`src/core/duration.ts`），命令行和应用共用，界面不另写。注意界面里已结束的活，`ViewJob.seconds` 已经扣过休眠，所以拼的时候不再让 `timeSplit` 扣第二遍（`lib/board.ts` 的 `timingLine`）；在跑的活没有 `seconds`，休眠由 `timeSplit` 扣。“表现”页的“平均：……”：档案里 `avgSteps`、`avgToolSeconds`、`avgSeconds` 都有时，才用 `describeTiming({ steps: 四舍五入的平均步数, toolSeconds: avgToolSeconds, thinkSeconds: max(0, avgSeconds − avgToolSeconds) })`（`lib/board.ts` 的 `averageTimingLine`）；任何一个是 `null` 就不显示这一行。
- **快速版和普通版**分开算，表格里同一格分两块（“普通版”“快速版”）。
- **被采用**：这一组里被拍板“用这份”的件数。
- **打分、返工、优点毛病、评语**：来自各家档案（`View.profiles`，由 `src/core/profiles.ts` 算好，和 `View.stats` 并存）。平均分不含只写了外部原因的件；返工比例是带“需要返工”标签的件数占打了分的件数；优点、毛病各最多 3 个标签，按出现次数排；评语是这一组最近 5 条。页面只显示，不自己算、不自己给标签分好坏。
- **通常多久**（在跑的卡片上的“通常 X”“大约还要 Z”“比平时久 Y”）：同一选手、同一类活、同一版本（快速版分开）、做完了的活，不到 3 件时一律不显示，只显示已用时。取这些活（已扣休眠）的中位数；不算停下、断了、出错的。由核心算好，放在每件活的 `typical`（秒）里，看板直接读。
- **额度的数据时间**：顶栏状态块的悬停提示和“各家表现”页每张额度卡都写“数据时间 MM-DD HH:mm”（本地时间）；超过 30 分钟，卡片上的时间用提醒色。某一家这次没查到，保留它上一次的数据和时间，并写“这次没查到”。
- **顶栏额度**：每家一个圆环（`QuotaRing`），表示这家本期用得最多的那个池的百分比（Cursor 三个池、Codex 两个窗口都取最大的一个）；环旁写百分比（只有环看不出来），不写池名，悬停整块看全部池、数据时间。
- **给人看的时间**统一是本地时间 `MM-DD HH:mm`（如 `09-29 14:44`），数据文件里仍存标准格式。

## 10. 设置页

设置是一个大尺寸 `Modal`（`size="lg"`、`flush`），像 macOS 的系统设置：**左边窄栏分页，右边内容区单独滚动**（`SideNavLayout`）。

## 11. 顶栏

顶栏就是窗口的标题栏，高 `--topbar-h`（48px），整条可以拖动窗口，里面的控件不可拖。macOS 左上角的红黄绿三个按钮（`trafficLightPosition`，在 `app/main/index.ts`）与顶栏垂直居中，顶栏左边给它们留 `--titlebar-inset`。没有品牌字（窗口标题和菜单栏已经写着“派活工作台”），单行，任何宽度都不换行、不隐藏右边的控件。

| 位置 | 内容 |
|---|---|
| 左 | 分段切换（`Segmented`）：“看板 ｜ 历史 ｜ 表现”。“各家表现”在顶栏简称“表现”，悬停提示写全名和快捷键（如“各家表现（⌘3）”），页面标题仍是“各家表现”。天天看的“看板”是默认页；当前页浮起 |
| 右 | 状态块（`StatusCluster`）：三家额度环 + 隔离自检小圆点，一个按钮，点一下去“各家表现”；后面是设置按钮（`.top-icon`，“三根滑杆”图标），悬停“设置（⌘,）” |

- 顶栏不放别的文字标签和数字。要更多细节，悬停或点进“各家表现”。

## 12. 通知与菜单栏

系统通知**只报结论和回复**，不催主人动手。

**只发两类：**

1. **负责人拍板了。** 任务上新出现 `decision.by === 'lead'` 时发一条。用了这份：“[题目]：用了 [选手名/模型名] 那份——[结论前 40 字]”。没用：“[题目]：没用——[结论前 40 字]”。没有结论就不写破折号。同一批里多件同时拍板，合成一条，题目用这一批的题目，点通知打开这一批；只拍了一件就打开那一件。
2. **负责人回复了主人的留言。** 一条负责人留言紧跟在主人留言后面才算；正文是“[选手] · [题目]：负责人回复了你的留言：[前 30 字]”，更长加省略号。点通知打开那一件。

不再发：做完等挑、一批等挑、出错、失联、验收没过、真实验收的结果。

同一条只发一次。应用启动时已经存在的不补发。设置里关掉系统通知就不发；关掉期间出现的，再打开也不补发。旧的通知键不迁移，新种类用新的键。

菜单栏图标旁边只显示在跑的件数，不带事项小圆点。下拉菜单先是“在跑的活”，再是“验收中”；没有时写“没有在验收的活”。

## 13. 真实验收

真实验收由负责人执行并记录，不打扰主人。

### 弹窗“真实验收”一节

只在这件活的 `realCheck` 存在时出现（没有就没有这一节），放在“结果”之后、按钮之前，用 `Section`，标题是一行状态“真实验收：<状态标签>”：

| 状态 | 什么时候 | 标签 |
|---|---|---|
| 待做 | 需要真实验收，还没有结果，也没有写明不需要 | 中性（`neutral`） |
| 通过 | 有结果且通过 | `ok` |
| 没过 | 有结果但没过 | `bad` |
| 不需要 | 负责人写明了不需要（或本来就不需要） | 中性 |

- 下面依次是：负责人的说明（通过、没过时是结果的说明，写成“负责人：……”；不需要时写“不需要的理由：……”）、检查步骤（有序列表，一条一句）、有结果且截图不为 0 时写“附 N 张截图”（这一版只写张数，不显示图）。
- **“待做”不催主人**：只是描述状态，那是负责人的事；不出现按钮，也不出现“请”“需要你”。
- 说明、步骤一律纯文字。看板卡片和一批的弹窗不显示这一节。

## 14. 看板的列

看板固定三列，从左到右：进行中、验收中、已完成。**“排队”不再单独成列**（五列同时出现太挤）。

- **排队并进“进行中”**：排队的活放在进行中列**最上面**（先于在跑的），用统一的卡片写法：一张 `Card`（紧凑款），里面是 `WorkerRow`（图标、模型名、强度标签），最右边是灰色小标签 `Chip`“排队”（中性色，`--sunk` 底），下面一行灰色的题目。一批里有的在跑、有的在排队，在跑的照旧成组，排队的各自一张放在最上面。
- **列头的件数**：写“在跑几件”，有排队时后面再加一段“· N 排队”（如 `2 · 1 排队`）；没有排队就只有一个数字。这样数字始终和列名“进行中”的意思一致，排队的另说，一眼看得出还有几件没开始。前一个数字 `data-testid="running"`，“· N 排队”是 `data-testid="queued"`，没有排队时不出现。进行中列一件都没有（没有在跑，也没有排队）时写“现在没有在跑的活”。
- **设置里的列颜色**没有“排队”一项；`defaultColumns` 只有三个键（running、attention、done）。
- **列头任何宽度都不折行**：列名、件数、“· N 排队”、“· 近 24 小时”、“全部历史 →”都 `white-space: nowrap`，列名和件数不缩。每一列是一个容器（`container-type: inline-size`，名字 `col`），列头按列宽收：
  - 列宽 < 300px：“· 近 24 小时”隐藏（悬停在件数上仍能看到，`title`）；
  - 列宽 < 240px：“全部历史 →” 只留“历史 →”（“全部”隐藏）。
  文字永远不换行、不截断；隐藏靠容器查询，不靠猜窗口宽度。窗口 ≤860px 时看板上下排列，每列满宽，什么都不用收。
- **卡片里模型名的截断规则不变**（第 3 节 `WorkerIdentity`：只截模型名，标签、用时不截）。三列平均分宽度，检查时以 900 宽、三列同时出现为准。

- **项目标签**（同时有不止一个项目时才出现）：“看板上的项目数”按所有卡片一起数（排队、在跑、验收中、近 24 小时已完成），大于 1 才算“同时有多个项目”。这时**进行中、验收中**两列每张卡片的题目旁放一个很小的项目 `Chip`（中性色，靠右，名字长了截断、悬停看全名）：排队卡、在跑卡、验收卡都带；一批同时在跑的大卡带在批题目旁，组里每一家的行不再重复。只有一个项目时一个标签也不写。项目的显示名取自 `View.projects`，没有项目名的老记录写“未归类”。
- **已完成列按项目聚合**（一个项目一张卡，像两家对比那张卡把结果收在一起）：不管有几个项目，**一个项目一张卡**（`BatchGroup`，外面包一个 `section`，可访问名是项目名）。标题栏写项目名（加粗）和近 24 小时的件数（`--muted`）；卡里一件活一行（`MemberRow`，点了打开详情）：选手小图标（`WorkerIdentity` 的 `sm` + `iconOnly`；一批有几家就几个，被采用那家照常、其余调淡）、题目（截断，悬停看全文）、用时（`--faint`，一批写最久的那家）、最右结果，**正常的不写、只标例外**（每行挂“用了这份”是废话）：采用了什么都不挂（一批里没采用的那家图标调淡 `.icon-dim`，用了谁一眼能看出）；没用的写淡色“没用”（一批都没用写“都没用”），整行题目和图标调淡；等负责人处理、已停照写。结果最多占这一行的 45%，放不下截断。一批的行最前面带批次色点。每张卡**最多 5 行**，新的在上；卡底右边是淡色“还有 N 件”（没有多的就不写，不能点）和朴素的“这个项目的全部 →”，点了去历史页并**选中这个项目**。项目按各自最近完成的一件排。行里不再写项目名，卡的标题栏已经说明。**标题栏**分两块：左边是折叠按钮（`.done-head`，`aria-expanded`；依次是折叠箭头 `.disclosure`、项目名、件数；展开朝下、折起来朝右，悬停背景 `--sunk`），右边是淡色 `MoreMenu` 的“…”按钮（可访问名“更多操作：<项目显示名>”，折起来也看得到）；点“…”或在标题栏任意处右键只打开同一菜单，不改变折叠状态，右键不弹浏览器菜单。折起来整张卡只剩这一行，展开才有任务行和卡底。**默认折起**（打开时只看项目名和件数，想看再点开）；点开了哪些记在本机（`localStorage` 的 `xa.done-expanded`，读写失败就当全都折起；以前的 `xa.done-collapsed` 读的时候删掉）。列头的件数是这一列里没归档的件数，“全部历史 →”照旧。
- **归档**（2026-09-30）：已归档项目的整张卡不出现在已完成列，列头件数也不算它们。进行中、验收中两列不变：这些项目在跑、在验收的活照常显示，项目小标签照常。已归档项目如果只剩已完成的活，这些卡不在看板上，也不算进“看板上的项目数”；在跑、在验收的仍算。项目卡**标题栏右边**的“…”先打开菜单，再点“归档”才归档；菜单里只有一项“归档”，不写说明（去哪找回由归档后的提示条说）。标题栏任意处右键在鼠标位置打开同一个菜单，两种入口都不折叠或展开卡片。选菜单项后按 `View.projects` 里 `archived` 的名字，加上这一个，整份交给 `setSettings({ archivedProjects })`（整份替换，不读设置里的名单）。保存成功才用 `Toast` 显示“已归档 <项目显示名>，可在历史页“已归档”里找回”和“撤销”；撤销从最新看板归档名单只移除这个项目，再存整份名单，成功后关掉这条提示（不关闭期间替换的新提示）。保存期间沿用单次写入保护。主进程校验这份名单：须为数组，最多 200 个，每一项是合法项目名（字母、汉字、数字、下划线和连字符，最长 64，不能是 `.` 或 `..`）；不是数组、名字不合法、超过 200 个都拒绝。不认识的设置字段照旧拒绝。卡等看板数据推回来就消失。保存失败时卡还在，用提示条写“保存失败：……”和原因（和设置保存失败同一套，`.notice.notice-bad`，`role="alert"`）。没有项目名的老记录（空项目名，显示“未归类”）不放“…”且标题栏右键不弹操作菜单。卡底只有“还有 N 件”（有才写）和“这个项目的全部 →”（靠右）。
- **只有一个项目时**不分组、不画组标题，直接列最近 10 件；多于 10 件时列底同样写“还有 N 件”，右边“全部历史 →”（去历史页，选“全部”）。

## 15. 表现（仪表盘）

“各家表现”是一页仪表盘。页面标题“表现”，副标题一句话说清口径（token 是三家各自报的数、额度是各家套餐的百分点、不到 3 件淡显）。从上到下：

- **筛选一行**（只在最上面一处，管下面所有仪表盘内容）：时间范围 `Segmented`（今天 / 近 7 天 / 近 30 天，缺省近 7 天）；项目小胶囊（和历史页的类型筛选同一套 `.filters`，“全部项目”在前，然后是这段时间有活的项目，按件数从多到少；只有一个项目时不出现）。选了什么记在本机（`xa.dash-range`、`xa.dash-project`）。数全部来自 `View.dashboard` 里“范围 + 项目”那一份，界面不自己算。这段时间一件都没有时，下面只写一句“这段时间没有结束的活。”
- **大数一排**（`StatTile`，自动换行，每块最窄 160px，一排高度一致）：做完（件，口径小字写“另有 N 件出错或中断”或“共 N 件，没有出错”）、采用率、平均分（一位小数）、总用时（扣休眠）、新读入 token（大数用“万”“亿”，小字写写出、缓存命中、几件没有记录）。**“做完”和“新读入 token”两块在大数右边带一条小趋势线**（`Sparkline`，这段时间每天的数；选“今天”只有一个点，不画）。满页柱状图重复，每天的走势不单独画图，收进这两块卡片。
- **额度花费**：大数下面单独一条横栏（`.pool-strip`）：“额度花费”，然后一行排开每个池“池名 **N 点**”（名字写全，算不出写“—”），右边淡色一句“各家套餐的百分点；同时有别的活在跑时按用量分摊”。不到 1 点写两位小数。
- **各家对比**：一张表，行是这段时间有活的选手（`WorkerIdentity` `detail="model"`），列是件数、采用率、平均分、返工、每件用时、每件新读入、每件写出、每件额度；数字右对齐、等宽数字；没有写“—”；不到 3 件的行淡显（`--muted`），悬停说“不到 3 件，还不能下结论”。用时和 token 取中间值；每件额度取平均（各家额度多按整数跳，一件小活常常是 0）。
- **按项目**：只在“全部项目”且不止一个项目时出现，和“各家对比”同一种表：项目、件数、用时、新读入、写出。不用横条。
- 然后是额度卡（第 9 节）和原来的“选手 × 活的类型”表（下面一行淡色小字“全部时间的积累；点一格看最近的评语。”）。

图表规矩（照 dataviz 方法）：这一页只有小趋势线一种图，单系列只用一个颜色 `--chart`（浅色 #2f6bd8、深色 #5f93ef，两种底色都过了亮度带和 3:1 对比的校验）；2px 细线、同色 10% 的底色、最新一天（或悬停那天）一个 8px 圆点带 2px 底色描边；纵向按这组数自己的最大值缩放，只看走势不读刻度，所以不画坐标轴。悬停或键盘聚焦某一天出提示（`chart-tip`：数在前加粗、日期在后）；每一天是一个透明按钮，可访问名“日期：数”。名字、数字一律纯文字。

下面是额度卡（第 9 节；额度卡上方一行：左边小节标题“额度”，右边是“刚刷新过”（有才写）和“刷新”按钮，两者**始终靠右**，刷新前后位置不变，标题和按钮垂直居中，`.sec-head` + `.sec-tools`），下面是“选手 × 活的类型”的表格，数字全部来自 `View.stats` 和 `View.profiles`（第 9 节）。第一列是 `WorkerIdentity`（`detail="model"`）；行是这两份数据里出现过的选手（按选手名单的顺序），列是出现过的活的类型。

- **一格一组**：同一格里普通版、快速版分成两块，块上写“普通版”“快速版”（只有普通版一块时不写）。每一块从上到下：
  1. 原有内容照旧：合格（“2/3 合格”或“验收 —”）、平均用时、被采用几次（第 9 节）；
  2. 平均每步的时间：在原有内容（合格、平均用时、被采用）之后、打分之前，单独一行，“平均：”加 `describeTiming` 的那句话（如“平均：大部分时间在想，跑命令不到 1 分钟，共 45 步”），`--muted` 颜色、正文字号，悬停写“只算做完了、有每步记录的活”。这一组还没有样本（`avgSteps` 是 `null`，或没有平均用时）时整行不出现，不写“—”；格子淡显（`.thin`）时跟着一起淡。
  3. 打分：有打了分的件时写“4.3 分”（一位小数，加粗）和“返工 33%”（百分比取整；分数悬停写“N 件打了分的平均分”，返工悬停写“打了分的 N 件里，带‘需要返工’的比例”）；这一组还没有打了分的件（包括只写了外部原因的），写灰色的“还没有打分”；
  4. 标签：优点用 `Chip` 的 `ok`，毛病用 `Chip` 的 `bad`，先优点后毛病，放不下就折行；悬停写出现了几次。没有就不画。
- **淡显**：做过的件数不到 3 件，或者已经有打分但打了分的件不到 3 件（档案的 `small`），这一块整体变淡（`.pcell.thin`），意思是样本少、还不能下结论。只是做得多但还没打分的，不淡显，只写“还没有打分”。同一格里两块各自判断。
- **点一块展开评语**：这一组有评语时，整块是一个按钮（`aria-expanded`），悬停背景 `--sunk`，展开时保持 `--sunk`。点了在这一行下面插一整行（跨满所有列），标题是“选手身份 + 类型标签 + 快速版标签（快速版才有）+ 最近的评语”，下面是最多 5 条评语，新的在上：每条第一行是题目（加粗）、分数小标签（“4 分”，没有分数不画）、时间（`MM-DD HH:mm`，`--muted`）；下面分行写“做得好：……”“要改进：……”（没有就不写）。同一时间只展开一块，再点一下或点别的块就换过去。没有评语的块不是按钮，点了没反应。
- 题目、评语一律当纯文字显示，保留换行，过长折行。

## 16. 历史页

历史页是**两栏**（`SideNavLayout`，`className="history-layout"`，不另造第三种两栏），左边是项目，右边是选中范围里的活。页面标题“历史”在右栏最上面，下面一行淡色小字写范围和件数（“画布 · 共 9 件。同一道题派给几家的算一件……”）。

**左栏**：第一行“全部”，然后每个没归档的项目一行，按最近活动从近到远排（用最近一件活的开始时间）；登记了但还没有历史的项目排在最后。每行：项目名（截断）、右边件数（一批算一件）、名字下一行小字“最近一次”：今天写“今天 14:30”，昨天写“昨天”，更早写“09-29”；没有历史写“还没有历史”。项目名单来自 `View.projects`（登记处的项目，加上任务里出现过但没登记的），显示名取 `label`；没有项目名的老记录归到“未归类”。选中哪一行记在本机（`localStorage` 的 `xa.history-project`，空串是“全部”，和设置页记分页同一种做法：读写失败不影响使用，回到“全部”）；记着的项目已经不在名单里也回到“全部”。看板已完成列卡底的“这个项目的全部 →”改的就是这个选中状态。窄窗口（≤860px）左栏改成顶上一排横着的页签，右栏整页往下排。

**已归档**：左栏“全部”和上面那些项目行只列没归档的。“全部”的件数、最近一次、右栏里的活，都不含已归档项目的活。左栏最下面另有一节“已归档”，放在 `SideNavLayout` 的 `footer` 里；没有已归档项目时这一节不出现。**分区标题像 macOS 侧栏的小标题**：没有底色，折叠箭头 `.disclosure` 在前（和已完成列同一套），淡色小字“已归档”（`--muted`、`--fs-xs`、加粗），件数靠右和上面的项目行对齐；悬停只变字色；是按钮（`aria-expanded`，可访问名“已归档 N 个项目”）。默认折起，点了展开。展开后每个项目一行，**和普通项目行一模一样**（名字、件数、最近一次；选中是 `--accent-soft` 底），行上不放任何按钮，名字不被挤。点项目行，右栏看它的历史，**右栏标题下面一行说明** `.arch-note`（`--sunk` 底、`--line` 边、`--r-md` 圆角、`--muted` 小字）：“这个项目已归档：不在看板上显示，也不能派活。记录和打分都留着。”，右边一个 `Button` 小号“取消归档”。点了不确认：把这个名字从归档名单里去掉，剩下的整份交给 `setSettings({ archivedProjects })`；项目回到上面的项目行，选中不变。校验和看板归档是同一套（第 14 节）。保存失败时名单不变，提示条写“保存失败：……”。已归档的项目仍算在名单里（选中记在本机，不会被弹回“全部”）。打开历史页时，如果本机记着的正是一个已归档项目，这一节先展开；否则保持折起。

**右栏**：
- 顶上一排按类型筛的小标签（“全部”加这个范围里出现过的类型；只有一种类型时不画）。记着的类型在当前范围里没有，就按“全部”显示，不留空。
- 按天分组，组标题是“今天”“昨天”“9 月 29 日（星期一）”（不是今年的带年份），天和天之间、每天里面都从新到旧；标题吸顶。一天一个面板（`Panel`），里面一行一件（同一道题派给几家的算一件，批次合并规则和看板一样）。
- **一行**从左到右：开始时间（`HH:mm`）、批次色点（多家一批才有）、类型 `Chip`、题目（截断）；靠右依次是：项目小标签（**只在“全部”视图里出现**，选了具体项目就不写）、干活选手的小图标（`WorkerIdentity` 的 `iconOnly`，每家一个）、有验收记录的一批写“合格 x/y”（第 9 节）、结果（正常的不写、只标例外）：采用了不挂标签（一批里没采用的那家图标调淡 `.icon-dim`）；`没用`、`都没用` 写淡色小字；`出错`（`bad`）、`失联`、`负责人在挑`、`已停` 用中性色 `Chip`。
- **点一行只展开，不弹窗**。展开后每家一行（`hmember`）：
  1. 统一的选手身份（`WorkerRow`，`detail="full"`：模型、强度、用时），最右边是这家的决定（采用了不挂标签；没用写淡色“没用”；主人自己点的决定照写）、有验收记录时的验收结果、有真实验收时的“真实验收：通过 / 没过 / 不需要 / 待做”；点这一行才打开这家的详情弹窗（悬停提示“打开详情”）；有未回复的留言时角上一个小红点；
  2. 结论：负责人写给主人的那句（拍板时的说明），没有就不写；
  3. 打分：写“4 分”（加粗）加打分标签，优点 `ok`、毛病 `bad`、其余中性（好坏由核心分，读 `ViewJob.rating.tags[].kind`，界面不自己分），下面分行写“做得好的：……”“要改进的：……”；只写了外部原因的写“没有打分”和“外部原因：……”；还没打分写淡色的“还没打分”。评语一律纯文字，保留换行。
  一批展开后底部右边有“打开这一批 →”，打开整批的弹窗。这里不再出现“结果：未验收”“决定：用了这份”这类表格字段。
- 空状态（`EmptyState`）：没选项目写“还没有历史。”，选了项目写“这个项目还没有历史。”。

数据：`ViewJob.project`（项目名）、`ViewJob.rating`（当前这一版打分：`score`、`good`、`improve`、`external`、`at`、`tags: { tag, kind: 'good' | 'bad' | 'other' }[]`，不带改分前的历史；没打过分是 `null`）、`View.projects`，都由 `src/core/view.ts` 只读算出，好坏分类在 `src/core/profiles.ts` 的 `tagKind`，和各家表现同一份。
