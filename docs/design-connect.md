# 接入其他 AI：让负责人跨压缩也记得用派活工作台（设计，2026-09-30）

这份文档先写查到的事实，再给方案。
调研原文（每条标了“文档 / 实测 / 源码 / 未查清”）：[Codex](research/connect-codex-2026-09-30.md)、[Grok](research/connect-grok-2026-09-30.md)、[Cursor](research/connect-cursor-2026-09-30.md)；Claude 部分来自官方文档（code.claude.com/docs 的 memory、skills、context-window、hooks 几页）。

## 1. 要解决什么

现在接入别的 AI 只有一个办法：复制一段提示词贴进它的对话（`src/core/intro.ts`）。提示词活在聊天记录里，对话一压缩就可能被概括掉，那个 AI 就忘了派活工作台：自己动手写，或者直接调用选手的命令行（绕过隔离、额度和记录）。

目标：**接入一次，以后每个新会话、每次压缩之后，负责人都知道这台电脑有派活工作台。** 规矩本身仍只放在指挥手册一份（`xagents guide`），提醒只需要做到“记得跑那条命令”——派活工作台本身就是记性，状态和规矩一条命令全拿回来。

## 2. 查到的事实（本机版本：Claude Code 2.1.283、Codex 0.159、Grok 1.0.44、Cursor 命令行 2026.09.28）

### 2.1 压缩之后，什么还在

| | 常驻规矩文件 | 技能清单 | 压缩前后能插话的钩子 |
|---|---|---|---|
| Claude | 在：CLAUDE.md、`~/.claude/rules/` 压缩后从磁盘重读（文档） | **不在**：压缩后清单不重新加载，只保留调用过的技能正文（文档原话 “The skill listing does not reload”） | 有：“会话开始（来源=压缩）”钩子的输出加进压缩后的上下文（文档） |
| Codex | 在：`~/.codex/AGENTS.md` 压缩后原样重新放回（实测） | 在（实测），但每条说明被砍到约 116 字 | 有 SessionStart(compact)、PostCompact（文档+源码，压缩后是否触发没实测） |
| Grok | 在：规矩块压缩后重新放回（实测，项目级） | 在（实测），每条说明约 200 字 | 有 PostCompact；但 SessionStart 的输出不进上下文（文档） |
| Cursor | 在：规矩和技能清单都在“初始上下文”里，压缩时原样保留（读本机一份真实压缩过的记录得出，没能自己触发压缩） | 在，但本机 165 个技能，每条说明只剩约 27 字 | sessionStart 注入的内容也在初始上下文里 |

**结论：四家里唯一处处可靠的是“常驻规矩文件”。** 技能清单在 Claude 上压缩就丢，在 Cursor 上被砍得只剩二十几个字，只能算锦上添花。

### 2.2 各家的全局规矩文件放哪

- **Claude**：`~/.claude/CLAUDE.md`，或用户级规矩目录 `~/.claude/rules/*.md`（每个项目都生效，文档）。
- **Codex**：`~/.codex/AGENTS.md`（有 `AGENTS.override.md` 时改用它），合并上限 32 KiB，本机现在约 7 KB。没有规矩目录。
- **Grok**：`~/.grok/AGENTS.md` 或 `~/.grok/rules/*.md`。**另外 Grok 默认就读 Claude 的 `~/.claude/CLAUDE.md`、`~/.claude/rules/`、`~/.claude/skills`**（`grok inspect` 实测看到）。
- **Cursor**：全局 User Rules 存在**云端账号设置**里，不是本机文件（命令行 `-p` 也会带上，实测）。本机文件形式：命令行从工作目录一路往上，每级读 `.cursor/rules/*.mdc`、`AGENTS.md`、`CLAUDE.md`（源码，未实测），所以家目录下的项目都能吃到 `~/.cursor/rules/*.mdc`。不读 `~/.claude/CLAUDE.md`。

### 2.3 执行命令前拦截（钩子）

四家都有，都实测拦下过 `echo zz-blocked`，理由都能回到模型：

- **Claude**：`~/.claude/settings.json` 的 PreToolUse；bypassPermissions 模式下也拦得住（文档）。
- **Codex**：`~/.codex/hooks.json` 的 PreToolUse，正式功能；但**每条钩子要主人在 Codex 里“信任”一次**（按内容哈希，钩子一改就要重新信任）；桌面应用里怎么信任没查清。
- **Grok**：`~/.grok/hooks/*.json`，不用信任；**出错、超时一律放行**。另外 Grok 默认也会跑 `~/.claude/settings.json` 里的钩子。
- **Cursor**：`~/.cursor/hooks.json` 的 beforeShellExecution，命令行里给模型的话要写在 `user_message`；另外会按名字映射执行 `~/.claude/settings.json` 里的 Claude 钩子（源码）。用户级钩子命令行是否执行没实测（源码支持）。

各家文档都说钩子是“护栏”不是“边界”：只能纠偏，挡不住刻意绕路（比如换个路径调用、写进脚本再跑）。

### 2.4 选手会不会读到给负责人的东西（交接说明这里不准）

| 选手 | 会读到 |
|---|---|
| Codex | `~/.codex/AGENTS.md` 和 `~/.codex/skills`、`~/.agents/skills`。`--ignore-user-config` **只跳过 config.toml**（实测）；隔离挡的是它跑的命令，不挡 Codex 程序自己读配置 |
| Grok | `~/.grok/` 下的规矩、技能、钩子，没有开关能关（实测）。**读不到** `~/.claude` 系列：派活工作台已关掉 Claude 来源开关，隔离也禁读 |
| Cursor | `~/.cursor` 下的一切、`~/.agents/skills`、云端 User Rules，没有开关能关（实测）；`~/.claude` 被隔离禁读 |

所以：**写在各家全局位置的“你是负责人”，选手多半也看得到。** 好在 `rules.md` 已经要求选手“忽略只对负责人有效的全局规则”，我们的那句话里再写明“选手忽略”即可。选手真去跑 `xagents` 也会失败（写不了 `~/.xagents`），不会造成破坏，只是浪费。

### 2.5 顺带发现的隔离漏洞（另开待办，不在本设计里修）

- **Cursor 选手能写整个 `~/.cursor`，包括 `~/.cursor/hooks.json`**。钩子由 Cursor 以主人账号执行、没有弹窗；选手留下一条，主人以后在隔离外打开 Cursor 就会执行。同类落脚点：`skills`、`rules`、`mcp.json`、`cli-config.json` 的权限项。
- **Grok 选手能写 `~/.grok/skills`、`~/.grok/AGENTS.md`、`~/.grok/rules/`**（钩子和配置已挡），写进去的东西会被主人以后的 Grok 读到。
- 已开待办“堵上 Cursor 和 Grok 选手写全局配置的隔离口子”。**本设计要在那一件修好之后再往 `~/.cursor`、`~/.grok` 写东西**，否则选手能改掉我们写的规矩和钩子。
- **2026-09-30 已修好**（主线 `002add1`，见 [research/global-config-writes-2026-09-30.md](research/global-config-writes-2026-09-30.md)）：选手只能写自己这件活的临时状态目录，各家全局配置一律不能写，自检加了对应探针。Cursor 接入还差一步：实测 `~/.cursor/rules/*.mdc` 在编辑器和命令行里是否生效。
- 较轻的两条（记下，暂不处理）：Codex 选手会带上主人全部全局规矩和技能说明，占上下文；以后可以学 multica，给每件活一个单独的 `CODEX_HOME`（只放登录）。Grok 选手读不到副本里的 `AGENTS.md`（项目没被信任），但平台派活时已把项目规则拼进题目，影响不大。

## 3. 对四层思路的评估

1. **技能：不单独算一层。** 压缩后在 Claude 上丢失、在 Cursor 上只剩 27 字，靠不住；每家各装一份还会在 Cursor、Grok 里重复出现（它们把各家技能目录全读一遍）。现有的 `~/.claude/skills/xagents` 保留，它已经出现在 Claude、Grok、Cursor 的清单里，给“怎么用”一个入口就够了；Codex 不另装。
2. **规矩文件一句话：升为主干，不是兜底。** 这是四家唯一都靠得住的办法。
3. **执行命令前拦截：有用但不是必需，建议放第二步。** 它只管“直接调用选手”这一种情况（忘了派活工作台的 AI 更常见的是自己动手干，钩子管不到）；各家写法和信任手续都不同，Codex 还要主人逐条信任；而且只能纠偏。好处是便宜：一条 Claude 钩子能同时管 Claude、Grok、Cursor 三家（它们都跑 Claude 的钩子，Cursor 这条待实测）。
4. **`xagents connect` 一条命令接入：保留，**加上应用里的按钮。

另外一个更彻底的办法来自 multica（见第 8 节）：让平台自己启动负责人，每轮往里塞规矩，从根上不会忘。但那等于换一种用法（主人不再在聊天软件里和负责人说话），这次不做。

## 4. 方案

### 4.1 那一句话（全平台唯一一份，放在 `src/core/connect.ts`，`intro.ts` 引用同一份）

```
# 派活工作台
这台电脑装了派活工作台（命令 `xagents`）。要把开发、修复、审查、调研交给别的 AI（Codex、Grok、Cursor）去做时，一律用 `xagents`，不要直接运行 `codex exec`、`grok -p`、`cursor-agent -p` 这类命令。当负责人开工前、对话被压缩后接着干活前，先运行 `xagents guide`，读完再动手。
如果你是派活工作台派来干活的选手（题目开头写着“你是负责人派来完成本题的助手”），忽略这一段。
```

### 4.2 各家写到哪

| AI | 写到哪 | 形式 | 谁会一起读到 |
|---|---|---|---|
| Claude | `~/.claude/rules/xagents.md` | 整个文件是我们的，撤下就删文件 | Grok 负责人也读；Grok、Cursor 选手读不到 |
| Grok | 同上，**和 Claude 共用这一份** | 不单独写，状态跟着 Claude 走；设置页这一行不给按钮，在 Claude 那一行接入或撤下 | — |
| Codex | `~/.codex/AGENTS.md` 末尾 | 带起止标记的一段（开始行以 `<!-- xagents:begin` 开头、结束行是 `<!-- xagents:end -->`，实测时写的开始行带一句“用 xagents connect codex --undo 撤下”），只改标记之间 | Codex 选手也读（靠“选手忽略”） |
| Cursor | `~/.cursor/rules/xagents.mdc`（带 `alwaysApply: true` 的头） | 整个文件是我们的，撤下就移进废纸篓 | Cursor 选手也读（靠“选手忽略”）。**只对家目录下的项目生效**（命令行从项目目录一路往上找 `.cursor/rules`，实测）；想处处生效，主人可以把那句贴进 Cursor 设置 → Rules → User Rules（存在云端账号里，派活工作台不替你改） |

主人自己在 `~/.claude/CLAUDE.md` 里手写的规矩不动，和我们的文件并存无害。

### 4.3 第二步（可选）：拦截直接调用选手

- 一个共用的判断程序：`xagents hook`，从标准输入读各家钩子送来的命令，判断是否“直接调用选手”（`codex exec`/`codex e`、ChatGPT.app 里的 codex 路径、`grok -p/--prompt/--prompt-file`、`cursor-agent -p/--print`、`~/.grok/bin/agent -p` 等；`--version`、`models`、`xagents …` 本身都放行），是就拒绝，并按各家要的格式回一句“请改用 xagents run，先跑 xagents guide”。判断规则只在核心里写一份。
- 装在 `~/.claude/settings.json`（Claude，顺带覆盖 Grok、Cursor，待实测）和 `~/.codex/hooks.json`（Codex，主人要在 Codex 里信任一次）。只合并我们那一条（按命令 `xagents hook` 认），主人现有的其他钩子原样保留。
- 选手那边：Codex 选手启动时关了钩子；Grok 选手关了 Claude 来源的钩子；Cursor 选手读不到 `~/.claude`。所以不影响选手。
- 程序不在、出错时一律放行，不会把负责人卡死。

### 4.4 `xagents connect`

- `xagents connect`：列出四家的接入状态（程序装了没、规矩写了没、拦截装了没）。
- `xagents connect <claude|codex|grok|cursor>`：写入；已写过就按最新内容更新；`--undo` 撤下。
- 规矩：
  - 只写 4.2 表里的文件；独立文件直接建或删，别人的文件只动标记之间那一段。
  - 第一次改动某个已有文件前，先把原文件复制一份到废纸篓（名字带日期），撤下时同样先备份。
  - 一律先写临时文件再改名；写前重读，内容和预期不符（主人刚好在改）就停下报原因。
  - 不读、不写任何密钥和登录文件；**不碰 `config.toml`**（Codex、Grok 的配置里可能有密钥）。
  - Grok 跟着 Claude 走，不单独接入或撤下，所以不用另记“谁接入了”。
- `xagents guide` 末尾“这台机器现在的情况”加一行接入状态。
- `intro.ts`（给其他 AI 的提示词）加一段：请那个 AI 征得主人同意后，把 4.1 那句写进它自己的常驻规矩文件。这样不在四家里的 AI 也能跨压缩。

### 4.5 桌面应用：设置 → 接入 AI（负责人自己设计、自己写）

- **第一个分组“一键接入”**：四行，每行左边是图标加名字（Claude、Codex、Grok、Cursor），名字下一行小字是核心给的一句说明；右边一个状态标签（已接入 / 不是最新 / 还没接入 / 没装 / 要看一眼，颜色表达）加最多一个按钮（接入 / 更新 / 撤下）。Grok 和 Claude 共用、没装的都不给按钮。细则以 `docs/ui-spec.md` 第 10 节为准。
  - 点“接入”前弹确认框，列出要改的文件和那段话原文；点“撤下”直接做，下面小字写“已撤下，原文件在废纸篓里”。
- **第二个分组“其他 AI”**：保留现在的复制提示词，说明改成“不在上面四家的 AI，把这段贴进它的对话；它会问你要不要把那句写进它的常驻规矩”。
- 桥上加三个白名单函数：`connectStatus()`、`connect(ai)`、`disconnect(ai)`。参数只认四个名字，其余一律拒绝；后台调核心，窗口不直接碰文件。
- 规范先改 `docs/ui-spec.md` 第 10 节，再写代码；截图查浅色、深色、窄窗口和确认框。

## 5. 怎么验收

每家都做一遍，全部在新会话里做：

1. **记得**：接入后开新会话，说“让别的 AI 帮我写个小函数”，看它会不会先跑 `xagents guide` 并用 `xagents run`。
2. **压缩后仍记得**：手动压缩一次（Claude、Codex、Grok 用 `/compact`；Cursor 用它的总结命令），再说一遍同样的话。
3. **拦截**（做了第二步的话）：让它直接跑 `codex exec "hi"`，看是否被拦、理由是否回到模型；`codex --version` 不应被拦。
4. **选手不受影响**：给 Codex、Grok、Cursor 各派一件只读小题，看日志和报告里它们没去跑 `xagents`。
5. **撤下干净**：`--undo` 后文件恢复原样（和废纸篓里的备份比对），状态显示“还没接入”。
6. **待实测项**：`~/.cursor/rules/*.mdc` 在 Cursor **编辑器**里是否生效（命令行已实测，见下）；Cursor 压缩后是否仍在（调研按本机一份压缩过的记录判断规矩在“初始上下文”里原样保留，没亲手触发压缩）；Cursor 和 Grok 是否执行 Claude 的 PreToolUse 钩子且理由能回到模型、Codex 桌面应用怎么信任钩子（做第二步时再测）。

**2026-09-30 已实测**（主人同意后写入真实配置：新建 `~/.claude/rules/xagents.md`；`~/.codex/AGENTS.md` 先备份到废纸篓，再在末尾加带标记的一段；两处都按 4.1 原文，验收通过，保留）：

- Claude 2.1.283：新会话能逐字引用那一段。在**同一个进程**里（`--input-format stream-json` 连发三句）手动压缩后，会话记录里压缩分界之后重新出现“规矩”附件（不只是压缩摘要），模型逐字引用出最后一句。
- Codex 0.159：`codex debug prompt-input`（不调模型）看到带标记的那一段在模型输入里。压缩后规矩文件原样放回，调研时已实测。
- Grok 1.0.44：`grok inspect` 列出 `~/.claude/rules/xagents.md (global) [claude]`。加上派活工作台给选手的那组开关后变成 `[disabled]`，选手读不到。同一会话 `-r <会话> -p "/compact"` 压缩后，会话记录里规矩出现两次（原始一次、压缩后重新放回一次），模型逐字引用出最后一句。
- Cursor 命令行 2026.09.28：写入 `~/.cursor/rules/xagents.mdc` 后，在家目录下新建的临时仓库里 `cursor-agent -p --trust --mode ask` 能逐字引用最后一句；对照组放在家目录外的临时仓库，回答“没有”（只看到技能清单里截断的 xagents 说明）。所以读到的确实是这份文件，也证实了“只对家目录下的项目生效”。
- 选手侧：第一次派给 Cursor · Grok 的只读小题启动即失败，原因是收窄临时目录后，路径长的副本里 cursor-agent 要在 `/tmp/.cursor/` 建连接文件被隔离挡住（与接入无关，主线 `072969f` 已修）。修好后同一道只读小题派给 Cursor · Grok 和 Codex 各一件：两家都在报告里写明看到了“派活工作台”那段、按其中“选手忽略”照常做题，命令记录里都没有调用 `xagents`，答案正确。Grok 选手读不到这份规矩（见上）。
- 测试会话记录都已移到废纸篓。

实测用临时目录；需要写真实配置的那几项，在主人点头后做，测完撤下，原文件从废纸篓备份比对确认一致。

## 6. 分工和顺序

1. 先修隔离漏洞（另一件待办）。
2. 第一步：核心 `src/core/connect.ts`（那句话、写入和撤下、状态、备份）+ 命令行 `xagents connect` + `guide` 加一行 + `intro.ts` 改说明 → 编码部分可以派给选手（Codex 擅长这类实现），完成后另派一家审查；界面部分负责人自己做。
3. 第二步（主人同意才做）：`xagents hook` 和两处钩子安装。
4. 每一步按第 5 节真实验收，负责人自己做。

## 7. 不做什么

- 不用“在命令路径里放同名替身程序”的办法拦截（会改本机工具设置、误伤主人自己在终端里打的命令）。
- 不往 `~/.agents/skills` 装东西（三家选手都读得到）。
- 不给每家各装一份技能。
- 不碰任何 AI 的 `config.toml`、登录文件、钥匙串；不改主人手写的 `~/.claude/CLAUDE.md`。
- 不做“平台自己启动负责人”（第 8 节）。

## 8. 参考：multica（multica.ai/docs）

开源项目（GitHub multica-ai/multica，约 5.2 万星，许可证写的是“其他”），思路和派活工作台很像：调本机各家命令行干活、每次运行一个工作目录、并发上限（每个 AI 默认也是 6）、技能、桌面应用；它也有“小队”，由一个领头 AI 分活。

- **可借鉴**：
  - 领头 AI 由平台启动，每一轮平台都往它的系统提示里追加固定规矩和成员名单，所以不存在“忘了”。这印证了“平台主动塞进去”比“提醒它去读”可靠。本设计能做到的对应物，就是各家压缩后都会重新放回的规矩文件。
  - 它把技能按次写进工作目录、跑完就删；Codex 每次用单独的 `CODEX_HOME`，从不写全局目录。这印证了第 2.4 节的担心，也是以后给选手单独 `CODEX_HOME` 的参考。
  - 领头的派完活就停，有人回报再被叫醒，和我们 `xagents wait` 的做法一致。
- **不照搬**：
  - 它明说不做隔离（默认各家最高权限，建议用户自己另开系统账号、容器或虚拟机），和我们的底线相反。
  - 它要服务器，工单和配置存在服务器上。
  - 它面向团队协作。
- **以后可选**：“平台自己启动负责人”，从根上解决记性问题；但主人就不能在聊天软件里直接和负责人说话了，要另外设计。
